# Plan: Async Benchmark Page-Fault Retry CLI

## Goal

Add an explicit page-fault retry budget CLI knob to `tokio_memmove_bench` so longer async throughput runs can distinguish the conservative default from diagnostic runs with a larger retry allowance.

## Scope

In scope:

- Add `--max-page-fault-retries <N>` to `tokio_memmove_bench`.
- Keep the default equal to `DEFAULT_MAX_PAGE_FAULT_RETRIES` (`1`) for compatibility.
- Use the configured value when building hardware `DsaConfig` for direct async and direct sync comparison paths.
- Record the configured retry budget in benchmark artifacts and validate it in verifier scripts.
- Add env plumbing for `verify_tokio_memmove_bench.sh` and `bench_async_throughput_matrix.sh`.
- Update CLI/verifier/matrix contract tests and README usage.

Out of scope:

- Changing the default retry budget.
- Treating larger retry budgets as performance-clean by themselves.
- Implementing preallocated/reused buffer slots.

Prepared-host spot check after host-free verification:

```bash
IDXD_RUST_BENCH_DEVICE=/dev/dsa/wq0.1 \
IDXD_RUST_BENCH_BYTES=16384 \
IDXD_RUST_BENCH_CONCURRENCY=1,8 \
IDXD_RUST_BENCH_DURATION_MS=1000 \

IDXD_RUST_BENCH_OUTPUT_DIR=target/async-throughput-retry-spot \
bash idxd-rust/scripts/bench_async_throughput_matrix.sh
```

## Outcome

Done. `tokio_memmove_bench` now accepts `--max-page-fault-retries <N>` with the existing default of `1`, records `max_page_fault_retries` in every benchmark artifact, and uses the configured value for both the direct async hardware path and direct sync comparison path. `verify_tokio_memmove_bench.sh` validates and forwards `IDXD_RUST_VERIFY_MAX_PAGE_FAULT_RETRIES`; `bench_async_throughput_matrix.sh` validates and forwards `IDXD_RUST_BENCH_MAX_PAGE_FAULT_RETRIES` and includes the retry budget as a CSV column.

Host-free verification passed:

```bash

devenv shell -- cargo test --manifest-path ./Cargo.toml -p idxd-rust --test async_benchmark_cli_contract --test async_benchmark_verifier_contract --test async_throughput_matrix_contract -- --nocapture
```

Result: `async_benchmark_cli_contract` 9/9, `async_benchmark_verifier_contract` 10/10, and `async_throughput_matrix_contract` 2/2 passed.

This confirms the new CLI knob can be used for retry-budget diagnostics, but it does not replace future preallocated/reused-buffer benchmark work for clean throughput comparisons.
