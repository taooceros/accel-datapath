# Plan: Legacy Code Module Split

## Goal

Move legacy and compatibility code out of the active top-level Rust modules so a reader can distinguish the current generic IDXD path from older compatibility surfaces without changing public behavior.

## Scope

In scope:

- Move the established blocking `DsaSession` implementation out of `idxd-rust/src/lib.rs` into a dedicated compatibility module.
- Move the hidden legacy async worker fixture out of `idxd-rust/src/async_session.rs` into a dedicated submodule.
- Preserve existing public imports such as `idxd_rust::DsaSession`, `idxd_rust::AsyncMemmoveWorker`, and `idxd_rust::AsyncWorkerFailureKind`.
- Update source guards and README wording so the separation is visible to future readers.
- Keep hardware verifier scripts truthful after the refactor by normalizing the repo launcher banner out of proof stdout while preserving `.stdout.raw` diagnostics.
- Keep launcher-backed verifier scripts runnable from outside the repository by entering `REPO_ROOT` before `devenv shell -- launch` and making caller-provided relative output directories absolute.

Out of scope:

- Renaming public APIs.
- Changing the generic `IdxdSession<Accel>` behavior.
- Changing hardware proof binaries or benchmark behavior.
- Reworking the direct async runtime, completion monitor, or DSA/IAX lifecycle.

## Intended Changes

1. Add `idxd-rust/src/legacy_dsa.rs` for the compatibility `DsaSession` implementation and re-export it from the crate root.
2. Add `idxd-rust/src/async_session/legacy_worker.rs` for the hidden blocking worker fixture and re-export only the compatibility types required by existing tests/downstream code.
3. Keep `idxd-rust/src/lib.rs` as documentation, module registration, and public re-exports instead of implementation storage.
4. Keep `idxd-rust/src/async_session.rs` focused on the direct async owner/handle/request/error surface and delegate the hidden fixture path to the new module.
5. Update contract/source-guard tests to fail if the compatibility implementation moves back into the active modules.
6. Update `verify_live_memmove.sh` and `verify_async_memmove.sh` to match the existing representative verifier behavior: keep wrapper stdout in `.stdout.raw`, normalize proof stdout for JSON/artifact comparison, and test that normalization in verifier contract tests.
7. Update launcher-backed hardware verifiers to run `devenv shell -- launch` from `REPO_ROOT` rather than the caller's current directory; keep output paths absolute so artifacts still land where the caller requested.
