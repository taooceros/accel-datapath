# Submit-occupancy huge-memmove probe plan

## Goal

Rerun Experiment 1 (`submit-occupancy`) with a deliberately huge memmove payload to test whether the known submission knee behaves like a consumer/completion-side effect or like device/PCIe/memory-path processing saturation.

## Scope

- Add a narrow way for submission-bottleneck experiments to request a custom memmove payload size.
- Preserve existing `noop`, `memmove64`, and `memmove4k` behavior and JSON naming.
- Run the focused hardware probe through `launch` on `/dev/dsa/wq0.0` with release `hw-eval`.
- Record the observed result under `docs/report/benchmarking/`.

## Intended change

Add a CLI knob for the memmove byte count used when `--dsa-op` selects a memmove operation. The default remains the existing fixed size for each operation class so old commands and reports remain comparable.

The special run will use 16 MiB payloads. Based on prior local DSA throughput around 30 GB/s, one 16 MiB memmove takes roughly 0.56 ms, much longer than the ~100 ns submit plateau and ~2.2 us first-completion timing in the earlier Experiment 1 report. This should make payload processing pressure visible if it is the controlling mechanism.

## Verification

- Run focused CLI/config tests covering the new knob.
- Build `hw-eval` in release mode.
- Run the focused hardware experiment via `launch`, not by directly executing the hardware binary.
- Check the JSON artifact for completed operations, missing completions, descriptor errors, and extra-submit latency by occupancy.

## Completion notes

Completed. The CLI gained `--dsa-memmove-bytes <N>` for custom memmove-size submission-bottleneck probes. The originally proposed 16 MiB size completed with descriptor errors on this WQ, so it is calibration evidence only. A clean 1 MiB run showed zero median descriptor errors and zero median missing completions across the checked occupancies; the first old completion moved to roughly 140--270 us, but the submit knee stayed around K=114--116. Results are in `docs/report/benchmarking/039.submit_occupancy_huge_memmove_2026-06-01.md`.
