# Experiment 2 codepath simplification plan

## Goal

Simplify the `submit-marker-overlap` Experiment 2 implementation without changing the benchmark contract or result schema.

## Scope

- Target the baseline overlap implementation in `hw-eval/src/benchmarks/submission_bottleneck/experiment_2_marker_overlap/overlap.rs`.
- Preserve the public selector, JSON fields, marker/poll semantics, and mechanism-probe module behavior.
- Keep the hot loop allocation-free beyond existing trace materialization.

## Intended changes

- Move per-iteration submit and poll trace bookkeeping out of the main benchmark loop into a small local helper.
- Move completion-observation arrays behind a focused helper so polling and post-submit drain accounting share one representation.
- Leave result aggregation and report structs unchanged unless a compile failure exposes an unused field.

## Verification

- Run targeted Rust tests for the `hw-eval` crate covering Experiment 2 helpers and CLI parsing.
- Run `cargo fmt` for the affected Rust files.

## Completion notes

Implemented. The overlap runner now delegates one benchmark configuration to `run_overlap_case`, keeps reusable benchmark scratch state in `OverlapScratch`, and encapsulates per-iteration poll traces plus completion observations in focused helpers. The one-shot TSC measurement helper is shared from `common.rs` and used by both the overlap runner and mechanism probes; raw `rdtscp()` remains only where a spin-wait needs an observation timestamp. Mechanism probe completion storage keeps explicit `completion`/`completion_mut` accessors because the storage owns both descriptors and completions, so indexing would obscure which field is selected. Mechanism probe polling uses one `poll_to_next_unfinished` path and keeps poll batching on the submit side via `poll_submit_batch_n`, meaning number of submitted requests between polls. The JSON/report schema and selector behavior are unchanged.
