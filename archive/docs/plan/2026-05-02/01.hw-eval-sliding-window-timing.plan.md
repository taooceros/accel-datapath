# Fix hw-eval sliding-window timing

## Goal

Correct hw-eval throughput measurements so sliding-window benchmarks do not count completions for descriptors submitted before the timed interval.

## Scope

- DSA direct sliding-window throughput (`memmove`, `copy_crc`).
- DSA pipelined hardware-batch sliding-window throughput.
- IAX direct sliding-window CRC64 throughput.

## Intended changes

- Start the throughput timer before initial window submission.
- Track the number of issued submissions explicitly in pipelined batch mode instead of relying on `completed + concurrency`.
- Drain only slots that were actually submitted when `iterations < concurrency`.

## Verification

- Run targeted `cargo test -p hw-eval` or narrower checks if the current workspace can build.
- If build is blocked by unrelated in-flight `idxd-sys` API redesign, report that explicitly and commit the focused source fix only.
