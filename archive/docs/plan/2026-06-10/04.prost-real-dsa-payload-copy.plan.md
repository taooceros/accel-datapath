# Prost real DSA payload-copy integration plan

## Goal

Integrate the real Intel DSA memmove engine into the generated Prost resumable async encode path so eligible `string` and `bytes` payload bytes can be copied by hardware while preserving normal synchronous Prost encoding bytes.

## Scope

- Work in the experimental DSA boundary under `accel-rpc/tonic/tonic-dsa-bytes-async` and the local Prost async encode tests under `accel-rpc/tonic/prost`.
- Keep CPU encoding as the default when no DSA work queue is configured or a payload is below `DsaConfig::min_message_bytes`.
- Keep `prost::Message::encode_raw` synchronous.
- Do not change Tonic codec encode plumbing; specifically avoid `tonic/src/codec/encode.rs`.
- Keep generated Prost payload offload routed only through `AsyncEncodeSink::poll_put_payload`.

## Intended changes

- Reuse the existing async DSA work-queue/config/retry machinery for Prost payload copies.
- Ensure the Prost sink reserves destination bytes in owned encode-buffer state before hardware submission, stores only stable raw pointers in pinned payload state while pending, and advances the buffer exactly once after successful completion.
- Preserve CPU fallback byte-for-byte compatibility with `prost::Message::encode`.
- Add or tighten non-hardware tests for CPU fallback and pending/resume behavior.
- Add an ignored hardware test that encodes a generated Prost message covering scalar, string, bytes, repeated payloads, map payloads, nested payload messages, and oneof payloads, then compares hardware output against normal synchronous Prost encoding and decode equality.

## Completion notes

- Added the real Prost DSA payload-copy sink in `tonic-dsa-bytes-async/src/prost_codec.rs`.
- The sink keeps CPU fallback as the default, selects DSA only when an explicit/shared work queue accelerates the payload length, reserves destination storage before submission, and advances the reserved bytes once after DSA success.
- Reordered the owned Prost encode future fields so pending payload state drains an in-flight descriptor before the message or encode buffer owner can be dropped.
- Expanded `tonic-dsa-bytes-async/tests/hardware_dsa.rs` with an ignored hardware test covering scalar fields, string/bytes payloads, repeated payloads, map payloads, nested payload messages, and oneof payloads. The test compares DSA-produced bytes against normal synchronous Prost encoding and decodes the DSA bytes back to the same message.
- `tonic/src/codec/encode.rs` was not changed.
