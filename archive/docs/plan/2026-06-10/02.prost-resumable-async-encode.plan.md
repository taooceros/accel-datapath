# Prost resumable async encode plan

## Goal

Redesign only the Prost-side async encode state so generated messages can suspend and resume `string` / `bytes` payload copies without changing Tonic body polling or Prost's synchronous encode path.

## Scope

- Modify Prost-side crates under `accel-rpc/tonic/prost/`.
- Keep `Message::encode_raw` and ordinary CPU encoding synchronous and byte-for-byte compatible.
- Do not modify Tonic `EncodeBody`, `EncodedBytes`, codec polling, or encoder traits.
- Keep sink policy responsible for synchronous copy versus future DSA offload.

## Intended changes

- Refine `PollEncodeState` so it can represent root and nested message cursors plus per-payload sink state.
- Generate poll-based encode code that writes keys and lengths once, then resumes pending payload copies without re-encoding prior structure.
- Support repeated `string` / `bytes`, maps with `string` / `bytes` keys or values, and nested message fields with explicit nested cursor state.
- Add tests using a sink that intentionally returns `Poll::Pending` to prove resume parity with synchronous Prost output.

## Verification

- Run targeted pending/resume tests for generated Prost messages.
- Run the existing Prost test suite for the modified workspace members.

## Completion notes

- `PollEncodeState` now keeps a root cursor, nested cursor stack, and sink payload state so generated encoders can unwind to the parent frame on `Poll::Pending` and re-enter the exact child frame on the next poll.
- Generated message, map, and oneof polling now routes nested messages through explicit poll helpers instead of forcing nested payloads through synchronous CPU message encoding.
- Added pending-once sink tests for scalar-only readiness, plain `string` / `bytes`, repeated payloads, maps, and nested messages; all compare byte-for-byte against synchronous Prost encoding.
- Verified with targeted async encode tests, full Prost workspace tests, and `git diff --check`.
