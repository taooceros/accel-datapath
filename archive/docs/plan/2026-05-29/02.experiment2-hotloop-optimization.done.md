# Experiment 2 hot-loop optimization

## Goal
Optimize `hw-eval` Experiment 2 (`submit-marker-overlap`) so the hot submit/poll path avoids avoidable allocations and observer bookkeeping while preserving the current result schema and trace data needed for analysis.

## Scope
- Modified only the Experiment 2 implementation and directly related plan/report artifacts.
- Preserved zero-based submit/request indices and existing JSON field names.
- Reused preallocated scratch storage for poll observations.
- Moved request-completion accumulator recording out of the submit/poll loop.
- Preallocated trace accumulator vectors for fixed per-iteration fields.

## Verification
- `cargo fmt -p hw-eval`
- `cargo test -p hw-eval experiment_2_marker_overlap`
- `cargo check -p hw-eval`
- `cargo build --release -p hw-eval`
- Focused `launch perf record` run for the same noop Experiment 2 profile shape used in report 029.
- Optimized perf reports generated with `perf report --stdio` and `perf report --stdio --no-children`.

## Outcome
- Hot-loop `CompletionPollResult` allocation/growth was removed by reusing capacity-`n` scratch vectors.
- Per-iteration sample trace vectors are now materialized after the submit loop from flat scratch buffers.
- Request-completion accumulator writes now happen after the submit loop from recorded status/TSC/index scratch arrays.
- Optimized perf captured 4951 `hw-eval` samples with zero lost samples.
- Report: `docs/report/benchmarking/030.experiment2_hotloop_optimization_2026-05-29.md`.
