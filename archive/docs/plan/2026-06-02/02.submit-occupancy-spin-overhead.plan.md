# Submit occupancy spin overhead option

## Goal

Add a manual CPU gap to Experiment 1 so submit traces can compare `noop` and large `memmove` under controlled extra submit-side overhead.

## Scope

- Add a `submit-occupancy` CLI knob for a fixed non-optimizable CPU-loop iteration count between descriptor submissions.
- Apply the artificial gap to the Experiment 1 prefill submit loop and traced post-prefill submit loop without changing the measured submit-call timing itself.
- Preserve existing defaults and JSON/report compatibility when the spin count is zero.
- Document the option and add targeted parser/contract coverage.

## Intended changes

- Extend `SubmissionBottleneckConfig` and CLI parsing with a zero-default `--submit-occupancy-spin-iters <N>` option.
- Thread the value into `bench_submit_occupancy_one_extra`.
- Add a small non-optimizable helper and use it after each submit except after the last submit in a contiguous loop.
- Include the configured spin count in Experiment 1 result rows for downstream plot labeling.

## Verification

Run targeted `hw-eval` Rust tests that cover config parsing, JSON serialization, and CLI contract behavior. Build/check the `hw-eval` crate after the change.

## Completion notes

Implemented `--submit-occupancy-spin-iters` with default `0`, threaded it through Experiment 1, recorded `spin_loop_iters` in result rows, and documented the intended comparison use for `noop` versus large `memmove`. The current helper is `for n in 0..iterations { black_box(n); }`, inserted between submissions and kept outside each recorded `submit_tsc_ticks` measurement.
