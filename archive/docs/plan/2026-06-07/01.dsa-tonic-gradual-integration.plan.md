# Gradual DSA integration for Tonic Prost

## Goal

Add a conservative first DSA integration slice to the vendored Tonic/Prost byte path. The first slice keeps normal Prost encoding unchanged by default, exposes a process-wide DSA configuration for experiments, and only uses DSA when the experiment explicitly enables it.

## Scope

- Add an opt-in `dsa` feature to `tonic-prost` using the repo-local `idxd-rust` DSA substrate.
- Add a process-global DSA configuration with device path and minimum message size.
- Add a controlled Prost encode path that stages the encoded protobuf bytes, submits one DSA memmove into tonic's output buffer, validates completion, and reports failures as gRPC internal errors instead of silently falling back to CPU copy.
- Keep the default no-DSA path byte-for-byte equivalent to the existing synchronous Prost encoder path.
- Add focused unit tests for global configuration and non-hardware policy/error boundaries.

## Non-goals

- Do not add async DSA futures into `poll_next` in this slice.
- Do not change generated service code or the normal tonic codec API.
- Do not claim a performance win from this slice.
- Do not require hardware for ordinary unit tests.

## Verification

- Run focused `tonic-prost` tests without the `dsa` feature to prove the default path remains healthy.
- Run focused `tonic-prost` tests with the `dsa` feature to prove the opt-in configuration and failure behavior compile and execute on an ordinary host.
- Run package checks for touched vendored crates.

## Completion notes

Implemented the first gradual DSA slice in the vendored Tonic fork. `tonic-prost` now has an opt-in `dsa` feature, exported process-wide DSA configuration helpers, and a Prost encode path that stages encoded protobuf bytes and submits a DSA memmove into tonic's output buffer when the global policy selects it. The default path remains the existing synchronous Prost encode path when the feature is disabled or no DSA config is set.

The DSA path does not fall back to CPU copy after a selected DSA failure. It reports setup or completion failure as a tonic internal encode error. Hardware-visible output buffer length is advanced only after the DSA copy reports successful completion.

Verification completed from `accel-rpc/tonic`: `cargo test -p tonic --lib`, `cargo test -p tonic-prost --lib`, `cargo test -p tonic-prost --features dsa --lib`, `cargo check -p tonic-prost`, `cargo check -p tonic-prost --features dsa`, and `git diff --check`. Root `git diff --check` also passed.
