# DSA submit-only measurement cleanup

## Goal

Make the submit-only benchmark output unambiguous enough to debug measurement artifacts before interpreting the hardware numbers.

## Scope

This pass stays inside `hw-eval` plus the existing benchmarking report. It will not add shared-WQ `enqcmd` or descriptor-completion/data-movement measurements. `rdpmc` was added after the user explicitly requested it during implementation.

## Intended changes

- Add an explicit `timer` field to submit-only latency JSON rows (`tsc`, `wall`, or `pmu`).
- Add fixed empty calibration rows for every submit-only timer pass using the same measurement path but no MMIO submission.
- Add `--submit-bursts` so operators can run either the default burst sweep or a single burst size for cleaner PMU/perf attribution.
- Rename the current stateful sustained workload output to `submit_only_pressure_ramp`, while keeping `--submit-mode sustained` as the CLI selector for that workload family.
- Preserve existing non-submit latency rows and avoid changing the full DSA/IAX benchmark behavior outside the submit-only additions.

## Verification

- Format and test the `hw-eval` crate.
- Build the release binary.
- Run a submit-only hardware check through `launch` with JSON output and inspect that timer labels, calibration rows, pressure-ramp naming, and burst selection are present.

## Completion notes

Implemented with a fourth submit-only timer pass named `rdpmc`, explicit JSON `timer` labels, empty calibration rows, configurable `--submit-bursts`, and `submit_only_pressure_ramp` output naming for the stateful no-drain workload. PMU ioctl/read overhead remains visible in empty calibration rows; `rdpmc` is the lower-overhead core-cycle path.
