# idxd-rust performance fix plan

## Goal

Improve the current `idxd-rust` DSA async benchmark path so measured throughput is not dominated by avoidable CPU validation, per-operation buffer generation, and an overly conservative page-fault retry budget. Keep the existing correctness/proof behavior available for validation-oriented runs.

## Scope

This first fix targets low-risk hot-path and benchmark-path issues that can be changed without redesigning the full async completion registry:

1. Add an explicit async memmove validation mode so proof runs can keep full byte verification while benchmark/performance runs can choose completion-only validation.
2. Thread that validation mode through `AsyncDsaSession`, `DirectAsyncMemmoveRuntime`, and `tokio_memmove_bench` CLI/config.
3. Reuse benchmark source data and destination capacity where possible instead of regenerating deterministic payload vectors for every operation.
4. Make page-fault retry settings visible and usable in the benchmark verifier path so larger transfers do not fail under the old single-retry default.

Out of scope for this first slice:

- Replacing the `HashMap`-based async pending registry with a slab/ring.
- Introducing a descriptor/completion pool.
- Adding a dedicated-WQ MOVDIR64B async submission path.
- Removing the dyn boxed public driver seam.

Those are larger runtime-design changes and should follow after the lower-risk measurement path is corrected.

## Intended changes

- Add a small enum such as `AsyncMemmoveValidationMode::{FullByteCompare, CompletionOnly}` with conservative default `FullByteCompare`.
- Extend direct-runtime config with the validation mode.
- In async success handling, always build the normal success report, but run `verify_initialized_destination` only in full-byte-compare mode. Completion-only mode will still set the destination length after a successful completion report.
- Add `--validation <full|completion-only>` to `tokio_memmove_bench`, defaulting to full validation to preserve existing behavior.
- Update hardware benchmark setup to open the async session with the selected validation mode and configured page-fault retry budget.
- Update benchmark mode loops to reuse deterministic source bytes per mode/seed pattern and reduce repeated allocation where simple and safe.
- Add or update host-free tests for CLI parsing, validation-mode defaults, and completion-only behavior using the test backend.

## Completion notes

Implemented the first-slice benchmark hot-path fixes:

- Added `AsyncMemmoveValidationMode` with default full byte comparison and an explicit `completion-only` mode for benchmark runs.
- Threaded the validation mode through the public direct async session open path, the hidden direct-backend test seam, direct runtime construction, and `tokio_memmove_bench --validation`.
- Kept success-report construction in both modes; completion-only now advances destination length after a terminal success without walking the copied bytes.
- Reused deterministic async benchmark source buffers and destination capacity in latency, concurrency, and throughput modes, while alternating source patterns to avoid stale-destination false positives in full-validation runs.
- Reused synchronous comparison buffers and made validation mode visible in JSON/text artifacts, verifier logs, and throughput-matrix CSV output.
- Documented the `IDXD_RUST_VERIFY_VALIDATION` and `IDXD_RUST_BENCH_VALIDATION` controls in `idxd-rust/README.md`.
