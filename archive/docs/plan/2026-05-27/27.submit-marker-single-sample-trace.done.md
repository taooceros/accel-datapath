# Submit marker single sample trace

## Goal
The current trace plot summarizes every submit index with medians/p99 over 1000 iterations. For debugging the codepath, show one concrete iteration trace instead.

## Intended change
Each `submit_marker_overlap` row will include `sample_trace`, a 160-point trace captured from one iteration. Each point records exact submit latency, poll latency samples, poll window, polled request range, and visible prefix for that specific iteration. Existing aggregate stats remain for compatibility.

## Verification
Use a release offset-1 run and verify the sample trace contains one point per submit index before plotting it.

## Completion notes
The benchmark now emits a concrete `sample_trace` for one iteration and the submit/poll trace plot renders that sample instead of per-index medians. Aggregate fields remain in the result for later statistical analysis, but the diagnostic plot now shows raw per-submit behavior.
