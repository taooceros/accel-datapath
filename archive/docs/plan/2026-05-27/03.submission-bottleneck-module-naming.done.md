# Submission bottleneck module naming refactor plan

## Goal

Rename the DSA bottleneck experiment module tree so the module name describes the measured bottleneck and each experiment file is numbered and easy to find.

## Scope

Refactor Rust module layout only:

- rename the bottleneck implementation module to `submission_bottleneck`;
- use the modern Rust module layout with `submission_bottleneck.rs` plus `submission_bottleneck/` child files instead of a directory `mod.rs`;
- name each experiment module as `experiment_N_name.rs`;
- keep `common.rs` for shared helpers.

No CLI selector, JSON schema, benchmark name, or hardware behavior should change.

## Intended changes

Expected layout:

```text
hw-eval/src/methodology/submission_bottleneck.rs
hw-eval/src/methodology/submission_bottleneck/common.rs
hw-eval/src/methodology/submission_bottleneck/experiment_1_submit_occupancy.rs
hw-eval/src/methodology/submission_bottleneck/experiment_2_marker_overlap.rs
hw-eval/src/methodology/submission_bottleneck/experiment_3_traffic_ladder.rs
hw-eval/src/methodology/submission_bottleneck/experiment_4_completion_reuse.rs
hw-eval/src/methodology/submission_bottleneck/experiment_5_blind_push_correctness.rs
```

Update imports, module declarations, and README structure notes.

## Verification plan

- `cargo fmt -p hw-eval`
- targeted CLI contract tests for bottleneck selectors;
- `cargo build --release -p hw-eval` to prove module layout resolves in release.
