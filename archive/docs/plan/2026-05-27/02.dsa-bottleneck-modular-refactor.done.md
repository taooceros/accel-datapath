# DSA bottleneck experiment module refactor plan

## Goal

Split the oversized DSA bottleneck experiment implementation into one Rust module per experiment so each runner is easy to find and maintain.

## Scope

Refactor only the implementation layout for the bottleneck experiments:

- Experiment 1: submit occupancy one-extra-submit latency.
- Experiment 2: marker completion overlap.
- Experiment 3: traffic-class ladder.
- Experiment 4: completion reuse policy.
- Shared descriptor/completion helpers used by those experiments.

This is a clean code organization refactor. It must not change CLI selectors, JSON schema fields, benchmark names, operation semantics, or hardware behavior.

## Intended changes

- Replace the single `hw-eval/src/methodology/submission_bottleneck.rs` file with a `hw-eval/src/methodology/submission_bottleneck/` module directory.
- Keep `mod.rs` small and declarative.
- Move shared helper types/functions into `common.rs`.
- Move each experiment runner into its own module:
  - `experiment_1_submit_occupancy.rs`
  - `experiment_2_marker_overlap.rs`
  - `experiment_3_traffic_ladder.rs`
  - `experiment_4_completion_reuse.rs`
- Keep public entry points re-exported under `crate::methodology::submission_bottleneck::*` so existing dispatch code stays boring.
- Update README structure notes to show the module directory.

## Verification plan

Because this is a refactor, verification must prove API and behavior shape are preserved:

- `cargo fmt -p hw-eval`
- targeted config parser tests remain green;
- targeted CLI selector contract tests remain green;
- release build of `hw-eval` succeeds.

Hardware smoke is not necessary for the claim if no hardware hot-loop semantics change, but if the compiler requires semantic fixes in moved code, run one minimal launcher smoke for the affected selector.
