# Tonic DSA mock bytes RPC throughput benchmark

## Goal

Add and run an end-to-end Tonic benchmark that compares the experimental DSA raw bytes codec against a standard CPU raw bytes codec using a mock bytes RPC.

## Scope

- Target crate: `accel-rpc/tonic/tonic-dsa-bytes-sync`.
- Benchmark unary request/response transfer through a real Tonic TCP client/server path.
- Keep the application body minimal: the server echoes raw `Bytes` and does no protobuf or business logic.
- Keep DSA opt-in through `TONIC_DSA_WQ` or `--dsa-wq`; use `launch` for the required `CAP_SYS_RAWIO` capability.
- Preserve a CPU baseline with the same raw `Buf`/`Bytes` message shape.

## Changes

- Added `src/bin/mock_bytes_rpc_throughput.rs` as a standalone executable benchmark.
- The executable starts a Tonic echo service, creates a Tonic client, validates payload echo correctness, performs concurrent warmup calls, and prints CSV throughput measurements.
- The standard codec uses CPU `BufMut::put` for encode and `copy_to_bytes` for decode.
- The DSA codec uses `DsaBufCodec` and opens a work queue from `--dsa-wq` or `TONIC_DSA_WQ`.
- Added `--dsa-min-message-bytes` so threshold policies can keep small payloads on CPU while using DSA for larger payloads.
- The throughput driver uses concurrent unary RPCs over `Channel` clones and reports `requests_per_s`, one-way MiB/s, and round-trip MiB/s.
- Server sockets use `TCP_NODELAY` via Tonic `TcpIncoming`, and each per-row server is shut down after measurement.
- Added the normal dependencies needed by the executable: `http`, `http-body`, `tokio`, and `tower-service`; enabled Tonic `transport` and `router` features for this crate.

## Usage

```bash
cd accel-rpc/tonic
cargo build --release -p tonic-dsa-bytes-sync --bin mock_bytes_rpc_throughput
cd ../..
launch accel-rpc/tonic/target/release/mock_bytes_rpc_throughput --codec both --requests 5000 --concurrency 64 --warmup 256 --dsa-wq /dev/dsa/wq0.0
```

Output columns are `codec,payload_bytes,requests,concurrency,elapsed_ms,requests_per_s,one_way_mib_per_s,round_trip_mib_per_s`.

## Verification

Observed locally:

```bash
cargo fmt -p tonic-dsa-bytes-sync
cargo check -p tonic-dsa-bytes-sync --bin mock_bytes_rpc_throughput
cargo check -p tonic-dsa-bytes-sync --benches
cargo build --release -p tonic-dsa-bytes-sync --bin mock_bytes_rpc_throughput
launch accel-rpc/tonic/target/release/mock_bytes_rpc_throughput --codec both --requests 5000 --concurrency 64 --warmup 256 --dsa-wq /dev/dsa/wq0.0
TONIC_DSA_WQ=/dev/dsa/wq0.0 launch bash -lc 'cd accel-rpc/tonic && cargo bench -p tonic-dsa-bytes-sync --bench buf_codec'
launch perf record -F 199 -g -o /tmp/tonic-standard-64.perf.data -- accel-rpc/tonic/target/release/mock_bytes_rpc_throughput --codec standard --payload-bytes 64 --requests 100000 --concurrency 64 --warmup 2048
launch perf record -F 199 -g -o /tmp/tonic-dsa-64.perf.data -- accel-rpc/tonic/target/release/mock_bytes_rpc_throughput --codec dsa --payload-bytes 64 --requests 100000 --concurrency 64 --warmup 2048 --dsa-min-message-bytes 1 --dsa-wq /dev/dsa/wq0.0
```

The benchmark ran both standard and DSA paths through `/dev/dsa/wq0.0`. Results, crossover follow-up, isolated encoder bench, and perf summaries are recorded in `docs/report/benchmarking/053.tonic_mock_bytes_rpc_throughput_2026-06-08.md`.
