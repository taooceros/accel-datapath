# Rust DSA page-fault retry

## Goal

Implement page-fault retry in the Rust DSA bytes codecs so `DsaCompletionStatus::PageFaultNoBof` is handled by touching the faulting page, adjusting the memmove descriptor, and resubmitting the remaining range instead of failing the encode.

## Scope

- Update `tonic-dsa-bytes-sync` and `tonic-dsa-bytes-async`.
- Share retry adjustment logic where practical.
- Preserve current successful fast paths, encoder-owned async buffer lifetime, and async drop-drain behavior.
- Do not add page pinning.
- Bound retry behavior so repeated no-progress faults fail clearly.

## Intended changes

- Add a small Rust retry helper for DSA memmove completions.
- Correctly interpret the DSA completion status write bit when touching `fault_addr`.
- Resubmit adjusted descriptors after retryable page faults.
- Add non-hardware unit coverage for adjustment and no-progress protection.
- Re-run hardware smoke and benchmark paths through `launch`.

## Verification

Run focused unit tests for both DSA crates, the ignored async hardware smoke test through `launch`, and the bytes RPC benchmark with async/sync DSA enabled.

## Completion notes

Completed. Both Rust DSA bytes codecs now retry `PAGE_FAULT_NOBOF` memmove completions by touching the reported fault address, advancing source/destination pointers by `bytes_completed`, rebuilding the descriptor for the remaining range, clearing completion state, and resubmitting. The write-status bit is handled with a write-only touch so tonic's uninitialized destination spare capacity is not read. Repeated no-progress faults are bounded and return a clear internal error.
