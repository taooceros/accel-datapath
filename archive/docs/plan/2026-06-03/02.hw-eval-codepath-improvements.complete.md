# hw-eval codepath improvements

## Goal

Investigate the current `hw-eval` execution path and make only source-grounded improvements that reduce correctness risk or remove avoidable benchmark-side effects.

## Scope

- CLI/config/report contract for count-like options and README-visible knobs.
- DSA benchmark descriptor-size and batch descriptor-list setup.
- Submission-bottleneck dispatch and Experiment 1 sentinel drain setup.

Out of scope: changing JSON result schemas, changing hardware status semantics that need spec/hardware confirmation, or running hardware benchmarks directly.

## Intended changes

- Reject zero for `--iterations`, `--max-concurrency`, and `--completion-reuse-window` before benchmark dispatch.
- Document `--threads` in the README as a submitter-thread count distinct from logical concurrency.
- Check DSA transfer sizes before descriptor fill instead of truncating `usize` to `u32`.
- Check batch sub-descriptor list alignment in release builds.
- Keep `submit-marker-overlap` limited to overlap rows; keep mechanism probes behind `submit-marker-mechanism` and `all`.
- Prebuild the Experiment 1 sentinel drain descriptor once and reuse it.
