# Submit-marker poll latency and polled index trace, 2026-05-27

## Question

The submit/poll trace needed direct polling latency, not only the post-submit polling window. It also needed to identify which request completion record was being polled, under the simplifying assumption that request completions are observed in order.

## Change

Experiment 2 now polls the completion prefix in order. At each submit index it polls from the first not-yet-observed request until the first incomplete request. The trace records:

- `poll_latency_tsc_ticks`: latency of individual status-read polls.
- `poll_latency_ns`: nanosecond conversion of that latency.
- `poll_count`: how many completion records were polled at that submit index.
- `first_polled_request_index` / `last_polled_request_index`: the request-index range polled at that submit index.
- `poll_window_tsc_ticks`: per-iteration `poll_end_tsc - submit_end_tsc`, i.e. median of deltas.
