# Shared WQ async vs raw direct memmove

## Scope

Device: `/dev/dsa/wq0.1`, shared WQ (`ENQCMD`). Both comparisons use direct/no-batch DSA memmove (`batch_n = 1`).

Raw baseline:

- `hw-eval`, `benchmark == "memmove"`
- single pinned submission thread, `--pin-core 2`
- `--iterations 5000`

Async benchmark:

- `tokio_memmove_bench`, `strategy = "tokio_naive_direct_descriptor"`
- same message sizes/concurrency values
- two async configurations matter:
  - default Tokio worker threads (`threads=128` on this host)
  - single Tokio worker thread (`threads=1`), which is closer to hw-eval's single submitter model

## Important caveat

The default async benchmark uses many Tokio worker threads, so it can submit ENQCMD from many CPUs. `hw-eval` is a single pinned submitter. Therefore default async-vs-hw-eval on a shared WQ is not an overhead measurement; it mixes runtime overhead with multi-submitter scaling.

## Apples-to-apples single-submitter comparison (`threads=1`)

Best async point per size compared to raw shared at the same concurrency:

| bytes | raw shared best | async shared threads=1 best | async/raw at same c |
|---:|---:|---:|---:|
| 128 | 5.073 Mops/s @ c=128 | 2.370 Mops/s @ c=8 | 0.467 |
| 256 | 5.076 Mops/s @ c=32 | 2.779 Mops/s @ c=32 | 0.547 |
| 1024 | 5.018 Mops/s @ c=128 | 2.003 Mops/s @ c=64 | 0.400 |
| 4096 | 4.622 Mops/s @ c=64 | 1.953 Mops/s @ c=8 | 0.433 |

So in the single-submitter shared-WQ comparison, the naive async wrapper keeps roughly 40%-55% of raw shared-WQ throughput at its best points.

## Default async worker-thread comparison (`threads=128`)

The default async run reached higher rates than single-thread raw at some points because it used 128 Tokio worker threads against a shared WQ:

- 128B: async best 6.490 Mops/s vs raw shared best 5.073 Mops/s.
- 256B: async best 11.694 Mops/s vs raw shared best 5.076 Mops/s.
- 1024B: async best 6.714 Mops/s vs raw shared best 5.018 Mops/s.
- 4096B: async best 5.412 Mops/s vs raw shared best 4.622 Mops/s.

Do not interpret those as negative overhead. They indicate that shared-WQ ENQCMD can scale with multiple submitter threads, while the current hw-eval shared baseline is single-threaded.
