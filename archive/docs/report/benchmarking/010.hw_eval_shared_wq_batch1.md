# hw-eval direct memmove on shared WQ `/dev/dsa/wq0.1`

## Scope

Compare corrected hw-eval direct/no-batch DSA memmove on:

- Dedicated WQ `/dev/dsa/wq0.0`: MOVDIR64B submission, `wq_dedicated=true`.
- Shared WQ `/dev/dsa/wq0.1`: ENQCMD submission, `wq_dedicated=false`.

Both use conceptual `batch_n = 1` (`benchmark == "memmove"`), `--iterations 5000`, sizes `128,256,1024,4096`, `--max-concurrency 128`, and `--pin-core 2`.

## Best direct memmove result by message size

| bytes | dedicated best | shared best | shared/dedicated | dedicated GB/s | shared GB/s |
|---:|---:|---:|---:|---:|---:|
| 128 | 9.384 Mops/s @ c=128 | 5.073 Mops/s @ c=128 | 0.541 | 1.201 | 0.649 |
| 256 | 9.384 Mops/s @ c=128 | 5.076 Mops/s @ c=32 | 0.541 | 2.402 | 1.300 |
| 1024 | 9.396 Mops/s @ c=32 | 5.018 Mops/s @ c=128 | 0.534 | 9.621 | 5.139 |
| 4096 | 7.346 Mops/s @ c=32 | 4.622 Mops/s @ c=64 | 0.629 | 30.089 | 18.932 |

## Interpretation

The shared WQ path is ENQCMD-bound at about 5.0 Mops/s for small and medium messages. Dedicated MOVDIR64B reaches about 9.4 Mops/s for 128B-1024B and about 7.3 Mops/s at 4096B. In this run, shared ENQCMD keeps roughly 53%-63% of the dedicated MOVDIR64B peak, depending on message size.

The shared WQ result is therefore a lower raw baseline for the current no-batch async wrapper if the wrapper is run against `/dev/dsa/wq0.1`. The prior async sweep was on `/dev/dsa/wq0.0`, so compare it to the dedicated MOVDIR64B baseline unless rerunning async on the shared WQ.
