# hw-eval batch-size-1 small-message recheck

## Question

Can `hw-eval` really report about 15 Mops/s for DSA memmove with batch size 1?

## Method

Use only `hw-eval` throughput rows with:

- `benchmark == "memmove"`
- direct descriptor submission
- no DSA `BATCH` descriptor
- conceptual `batch_n = 1`

Exclude `burst_memmove`, `batch_memmove`, `pipelined_batch_b*`, and `burst_batch_b*`.

Relevant source behavior in `hw-eval/src/methodology/dsa.rs`:

- `bench_sliding_window(..., "memmove", ...)` submits one descriptor per logical operation.
- The sliding-window timer starts after the initial window has already been submitted. This is reasonable for steady-state throughput, but with low `iterations` and high `concurrency` it can inflate results because a large fraction of the counted completions comes from pre-submitted operations.

## Results

Short run that previously produced suspicious results:

- `iterations = 300`
- small message sizes
- high concurrency
- one run reported up to about 15 Mops/s for 128B/256B/1024B.

Longer rechecks with `--pin-core 2`:

### 128B, iterations=50000

| concurrency | Mops/s |
|---:|---:|
| 1 | 1.647 |
| 2 | 3.136 |
| 4 | 4.083 |
| 8 | 4.606 |
| 16 | 7.518 |
| 32 | 8.269 |
| 64 | 7.597 |
| 128 | 8.502 |

### 256B, iterations=50000

| concurrency | Mops/s |
|---:|---:|
| 1 | 1.615 |
| 2 | 3.107 |
| 4 | 4.186 |
| 8 | 4.244 |
| 16 | 4.676 |
| 32 | 6.316 |
| 64 | 9.414 |
| 128 | 9.422 |

With `--cold`, 256B peaked at 9.394 Mops/s at concurrency 64 and 8.177 Mops/s at concurrency 128.

### 1024B

- `iterations=5000`, `--pin-core 2`: peak about 9.657 Mops/s.
- `iterations=10000`, `--pin-core 2`: peak about 9.509 Mops/s.
- A 50000-iteration full `hw-eval` run for 1024B timed out because the binary also runs other benchmark families.

### Existing 4096B dedicated artifact

`hw-eval/results_dedicated.json`, `cold_cache=true`, `iterations=5000`:

- peak direct `memmove` about 7.318 Mops/s.

## Conclusion

The 15 Mops/s batch-size-1 result is not a reliable steady-state result. It appears to be a short-run artifact from low iteration count and the sliding-window timer excluding the initial window submission.

After longer rechecks, direct/no-batch `hw-eval` small-message memmove is more like:

- about 8.5 Mops/s for 128B,
- about 9.4 Mops/s for 256B,
- about 9.5 Mops/s for 1024B,
- about 7.3 Mops/s for 4096B in the older cold-cache dedicated artifact.

So batch-size-1 can exceed 7 Mops/s for some small warm-cache runs on this host, but the earlier 15 Mops/s number should not be used as the raw baseline.
