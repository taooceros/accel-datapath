# hw-eval codepath audit, 2026-06-03

## Scope

Audited the current `hw-eval` codepath across CLI/config/report handling, the DSA benchmark execution path, and the submission-bottleneck experiments.

## Improvements applied

- `--iterations 0`, `--max-concurrency 0`, and `--completion-reuse-window 0` are rejected during config construction, before benchmark dispatch.
- README now documents `--threads <N>` as the DSA submitter-thread count, distinct from maximum logical concurrency.
- DSA descriptor transfer sizes are checked with `u32::try_from` instead of silently truncating `usize` values at descriptor fill sites.
- DSA batch sub-descriptor lists now have release-mode 64-byte alignment checks instead of relying on a debug-only assertion or no check.
- `submit-marker-overlap` now runs only the overlap experiment; `submit-marker-mechanism` remains the mechanism-probe selector, while `all` still includes both.
- Experiment 1 submit-occupancy prebuilds the drain sentinel descriptor once and reuses it, resetting only the sentinel completion before each drain submission.

## Findings left unchanged

The DSA batch throughput paths still contain hardware-status behavior that should not be changed without spec/hardware confirmation:

- Batch paths tolerate status `0x05` as success-compatible without a local named status constant or sub-completion verification.
- `bench_burst_batch` page-fault handling appears to touch the fault page and continue waiting rather than explicitly resubmitting/verifying the faulted batch before counting the round.

These are source-visible risks, but changing them can alter benchmark semantics and should be validated against the IDXD/DSA status contract and a hardware smoke run.
