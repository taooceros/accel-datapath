# Experiment 2 separate variant runs, 2026-06-02

## Method

Built release `hw-eval`, then ran each proposed Experiment 2 variant as its own `launch` invocation on `/dev/dsa/wq0.0`, pinned to core 0, 200 iterations per row. The run output is clean JSON; each JSON has a matching `.launcher.txt` with the exact command and launcher prelude.

Artifact directory:

- `docs/report/benchmarking/submission_bottleneck_2026-06-02/experiment2_separate_variants/`

Summary artifacts:

- `summary_overlap.csv`
- `summary_mechanism.csv`
- `summary_validation.csv`

Validation:

- Parsed 26 clean JSON files.
- Result rows: 21 `submit_marker_overlap`, 212 `submit_marker_mechanism`.
- Total clean JSON size: 5.42 GiB.
- Verification after code fix: `rtk cargo fmt -p hw-eval`, `rtk cargo test -p hw-eval`, `rtk cargo build --release -p hw-eval`.

## Code fix needed for the payload sweep

Validation exposed two Experiment 2 issues before finalizing the payload runs:

1. `--dsa-memmove-bytes` was parsed into the bottleneck config, but Experiment 2 ignored it and used the operation default payload size. The overlap and mechanism probe paths now receive `dsa_payload_size` and allocate/fill descriptors with that size.
2. Mechanism probes could timeout on large payloads and then reuse completion/data buffers while old DMA work was still in flight. The mechanism path now submits a DRAIN descriptor after timeout before the next iteration reuses those buffers.

The 1 MiB payload variant below was rerun after both fixes.

Observation: small payloads preserve the early-completion signal. The 1 MiB payload changes the regime: the first marker was not visible before the final submit, and only 140/160 completions were visible at the overlap measurement point before cleanup drain.
