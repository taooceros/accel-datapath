# DSA submit-occupancy one-extra result, 2026-05-26

## Question

For one logical operation per MMIO submission, does the latency of one extra DSA submit depend on the number of already-outstanding descriptors?

This is Experiment 1 from `docs/plan/2026-05-26/02.dsa-submission-bottleneck-experiment.plan.md`.

## Setup

- Binary: `./target/release/hw-eval`
- Runner: `--benchmark submit-occupancy`
- Device: `/dev/dsa/wq0.0`
- WQ mode: dedicated
- WQ size: 128
- DSA NUMA node: 0
- CPU pin: core 0
- Raw/JSON artifacts: `docs/report/benchmarking/submit_occupancy_2026-05-26/`

## Commands

Main sweep:

```bash
launch ./target/release/hw-eval \
  --accel dsa \
  --benchmark submit-occupancy \
  --device /dev/dsa/wq0.0 \
  --json \
  --iterations 1000 \
  --submit-occupancies 0,32,64,96,112,120,124,126,127,128,129,132,136,144,160 \
  --dsa-op noop \
  --pin-core 0
```

The same command was repeated with `--dsa-op memmove64`.

Fine knee sweep:

```bash
launch ./target/release/hw-eval \
  --accel dsa \
  --benchmark submit-occupancy \
  --device /dev/dsa/wq0.0 \
  --json \
  --iterations 3000 \
  --submit-occupancies 112,113,114,115,116,117,118,119,120,121,122,123,124 \
  --dsa-op noop \
  --pin-core 0
```

The same fine sweep was repeated with `--dsa-op memmove64`.

Baseline confirmation also ran `submit-only --submit-mode all` and `submit-admission` with the dense burst list. The admission baseline completed every descriptor at the checked bursts with zero missing and zero errors.

## Interpretation

The extra-submit latency is occupancy-dependent.

For NOOP, the extra submit stays in the cheap regime through `K=114` (`K+1=115` submitted), starts moving at `K=115`, and reaches the high/backpressured plateau at `K=116` (`K+1=117` submitted). The plateau is about 224--226 TSC ticks, roughly 101--102 ns on this run.

The 64 B memmove curve has the same shape and the same plateau. Its transition also starts at `K=115` and reaches the plateau at `K=116`. That means the first knee is not caused by 64 B payload DMA traffic; it appears before payload size is the differentiator. A 4 KiB variant was not run because the 64 B curve did not move the knee.

No run reported missing completions or descriptor errors. The admission baseline also completed all checked bursts with zero missing and zero errors, so this platform behaves like an admission-paced/backpressured dedicated WQ rather than silently dropping over-depth pushes.

The important result is that the first expensive extra submit appears before the nominal WQ size of 128. On this setup, the observed admission threshold is around 116--117 outstanding operations. The next experiment should test marker completion overlap to decide whether completions are becoming visible during the submit tail or whether the submit loop is mostly waiting for admission capacity to free.
