# Tokio tutorial async mechanism setup slide plan

## Goal

Add a short setup slide before the Go stackful / Rust stackless comparison. The new slide should explain why async needs an explicit suspension mechanism at all: when a task waits, its local variables, current control-flow position, and wake-up path must be preserved somewhere while the worker executes other tasks.

## Scope

Out of scope:

## Intended slide content

Working title: `Async needs a representation of paused work`.

Visible components:

- Opening sentence: `To let one worker run B while A waits, the runtime must preserve A as a resumable continuation.`
- Three boxes:
  - `where was I?` / `next instruction or state`
  - `what did I keep?` / `locals and borrowed/owned values`
  - `who wakes me?` / `waker or runtime queue handle`
- Closing sentence: `Stackful goroutines and stackless futures are two answers to where this continuation lives.`
