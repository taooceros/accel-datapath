# Submit occupancy TSC gap option

## Goal

Replace loop-count proxy pacing with an Experiment 1 inter-submit delay whose knob is actual TSC ticks.

## Scope

- Add a zero-default `--submit-occupancy-gap-tsc <ticks>` option for Experiment 1.
- Apply the TSC gap between prefill submissions and between traced post-prefill submissions, outside each recorded `submit_tsc_ticks` sample.
- Preserve existing `--submit-occupancy-spin-iters` compatibility for the prior `black_box(n)` loop, but prefer the TSC gap for new experiments.
- Record both configured gap fields in JSON rows so old and new sweeps remain distinguishable.
- Verify with cargo asm, focused tests, release build, and a focused hardware run.

## Intended changes

- Thread `submit_occupancy_gap_tsc` through `SubmissionBottleneckConfig` and the submission-bottleneck runner.
- Replace the single loop-count gap argument with a small `SubmitGap` helper that can apply either a TSC-targeted wait or the legacy black-box loop.
- Use the existing `read_tsc()` helper for gap timing.
- Update README, experiment docs, and reports with the new TSC-tick semantics.

## Verification

Run targeted `hw-eval` tests, release build, cargo asm on `submission_bottleneck::run`, and focused hardware rows comparing gap ticks 0/1/small values for noop and 1 MiB memmove.

## Completion notes

Implemented `--submit-occupancy-gap-tsc <ticks>` with default `0`, recorded `gap_tsc_ticks` in Experiment 1 JSON rows, and kept the legacy `--submit-occupancy-spin-iters` black-box loop mutually exclusive for compatibility. The TSC wait uses a non-serializing `rdtsc` helper and is applied outside each recorded submit measurement.

Verified with targeted config/report/CLI tests, `cargo fmt`, `cargo check`, release build, cargo asm inspection, and focused hardware rows for gap targets `0,1,10,25,50,100`. Findings are in `docs/report/benchmarking/044.submit_occupancy_tsc_gap.md`.
