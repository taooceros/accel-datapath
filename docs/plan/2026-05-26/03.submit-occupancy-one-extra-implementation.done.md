# Submit occupancy one-extra implementation plan

## Goal

Implement the first new DSA submission-bottleneck runner: occupancy-conditioned one-extra-submit latency.

## Scope

- Add an explicit `hw-eval` benchmark selector for the one-extra-submit experiment.
- Keep the code easy to find by placing the runner in a dedicated DSA bottleneck experiment module.
- Preserve existing submit-only, submit-admission, software-only, and full-suite behavior.
- Add JSON output for the new experiment without changing existing JSON rows.
- Add host-free CLI/config tests for selector parsing and invalid accelerator combinations.

## Intended changes

- Add `--benchmark submit-occupancy`, `--submit-occupancies`, and a narrow DSA operation selector for NOOP / 64 B memmove / 4 KiB memmove variants.
- Add a `submit_occupancy` JSON array with row fields for operation class, prefill occupancy, completed/missing/error counts, extra-submit TSC ticks/ns, and first-old-completion TSC ticks/ns.
- Implement each sample with unique descriptors and completion records for `K + 1` in-flight operations, no prefill polling, one timed extra submit, first-old-completion observation, and complete drain.
- Update README CLI/benchmark documentation.

## Verification

- Run targeted Rust unit tests for `hw-eval` config/report behavior.
- Run targeted CLI contract tests that do not require hardware.
- Build `hw-eval` to prove the hardware runner compiles.

## Completion notes

Completed. `hw-eval` now has an explicit `submit-occupancy` selector, `--submit-occupancies`, `--dsa-op`, a dedicated DSA bottleneck runner module, skipped-when-empty `submit_occupancy` JSON output, README documentation, and targeted config/CLI coverage.
