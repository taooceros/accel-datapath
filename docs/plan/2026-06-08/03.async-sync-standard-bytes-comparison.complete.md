# Async DSA vs sync DSA vs standard bytes comparison

## Goal

Compare end-to-end Tonic mock bytes RPC throughput for three encode paths: standard CPU copy, synchronous DSA bytes copy, and asynchronous DSA bytes copy through `poll_encode`.

## Scope

- Target workspace: `accel-rpc/tonic`.
- Add a comparison executable under a neutral benchmark crate.
- Reuse the same mock unary bytes echo shape as the existing sync benchmark.
- Keep DSA opt-in through `TONIC_DSA_WQ` or `--dsa-wq`, and run hardware through `launch`.
- Measure identical payload sizes, request counts, concurrency, and warmup for all three codecs.

## Intended changes

- Add a `compare_bytes_rpc_throughput` executable that can run `standard`, `sync-dsa`, `async-dsa`, or `all`.
- Make the benchmark generic over codec encode item type so standard/sync can use `Box<dyn Buf>` and async can use `Bytes` without changing the service shape.
- Wire benchmark dependencies in the benchmark crate.
- Record observed CSV results and interpretation in `docs/report/benchmarking/054.async_sync_standard_bytes_rpc_2026-06-08.md`.

## Verification plan

- Format and build the benchmark crate.
- Run benchmark crate tests and clippy.
- Run the release benchmark through `launch` with `/dev/dsa/wq0.0`.
- Record the observed results without extrapolating beyond the run.

## Completed changes

- Added `tonic-bytes-bench/src/bin/compare_bytes_rpc_throughput.rs`.
- Added the benchmark dependencies to `tonic-bytes-bench/Cargo.toml`, including `tonic-dsa-bytes-sync` and `tonic-dsa-bytes-async` for the two DSA comparison paths.
- Kept the service/client benchmark generic over `Codec::Encode`, allowing the same unary echo harness to compare `Box<dyn Buf + Send + Sync>` encode paths against the async `Bytes` encode path.
- Recorded the raw hardware CSV and interpretation in `docs/report/benchmarking/054.async_sync_standard_bytes_rpc_2026-06-08.md`.
