# Async DSA bytes transfer crate

## Goal

Add a separate experimental Tonic bytes codec crate that uses the `Encoder::poll_encode` interface to drive an asynchronous Intel DSA byte-copy operation.

## Scope

- Target workspace: `accel-rpc/tonic`.
- New crate: `tonic-dsa-bytes-async`.
- Keep the implementation hardware-specific inside the new crate; do not add DSA details to `tonic` or `tonic-prost`.
- Preserve the ordinary CPU path when no DSA work queue is configured.
- Use `poll_encode` to hold explicit in-flight DSA state and return `Poll::Pending` while hardware completion is outstanding.
- Use a direct final-buffer DSA destination under the stable-buffer experiment assumption.

## Intended changes

- Add a `Bytes`/`Bytes` codec with `DsaAsyncBytesEncoder` and `DsaAsyncBytesDecoder`.
- Add process and explicit work-queue configuration for an async DSA work queue.
- Implement a pinned pending-copy state that owns the source `Bytes`, direct destination pointer, descriptor, and completion record until terminal completion.
- Add drop-time completion draining for submitted operations so descriptor, completion, source, and destination storage are not freed while hardware may still access them.
- Add tests that cover CPU fallback and a deterministic pending encode path through Tonic's `EncodeBody`.

## Verification plan

- Format the new crate and workspace manifest changes.
- Run targeted tests for `tonic-dsa-bytes-async`.
- Run a targeted check for `tonic-dsa-bytes-async`.

## Completed changes

- Added `accel-rpc/tonic/tonic-dsa-bytes-async` and registered it as an `accel-rpc/tonic` workspace member.
- Implemented `DsaAsyncBytesCodec`, `DsaAsyncBytesEncoder`, and `DsaAsyncBytesDecoder` for raw `Bytes` payloads.
- Added process-wide and explicit DSA work-queue configuration APIs for the async crate.
- Implemented a heap-pinned pending DSA copy state. It owns a cloned source `Bytes`, hardware descriptor, completion record, and direct destination pointer into Tonic's encode buffer, and drains submitted descriptors on drop before releasing storage.
- Kept the original item in Tonic's `poll_encode` `Option` while returning `Poll::Pending`, then consumed it before returning `Poll::Ready`.
- Added a low-level delayed `EncodeBuf` commit path so async DSA can write directly into the final encode buffer under the stable-buffer experiment assumption.
- Added behavior tests for CPU fallback and a deterministic pending encode path through `EncodeBody`.
