# DSA payload latency benchmark

## Goal

Add a focused `hw-eval` DSA benchmark that measures end-to-end completion latency for one DSA memmove operation while varying payload size.

## Scope

- Add a CLI-selectable benchmark for single-operation DSA payload latency.
- Reuse existing `--sizes`, `--iterations`, `--device`, `--json`, `--cold`, and `--pin-core` controls.
- Emit results through the existing latency result JSON shape for compatibility.
- Run the requested hardware measurements for 1 MiB, 10 MiB, 100 MiB, and 1 GiB through `launch`.

## Changes

- Added DSA-only `--benchmark payload-latency`.
- The benchmark emits latency rows named `payload_latency`.
- The measurement path submits one DSA memmove descriptor, polls its completion, and records submit-to-completion TSC ticks.
- The focused payload benchmark uses size-aware warmup with a 64 MiB warmup byte budget instead of the old fixed 100 warmups per size.
- Source and destination payload pages are pre-touched before DSA submission.
- Large-transfer page-fault completions are retried during warmup/measurement setup instead of being silently accepted.

## Verification

- `rtk cargo fmt -p hw-eval`
- `rtk cargo test -p hw-eval --test cli_contract`
- `rtk cargo test -p hw-eval config::tests::remaining_dsa_only_benchmarks_reject_iax`
- `rtk cargo build --release -p hw-eval`
- Hardware run through `launch`:
  `launch ./target/release/hw-eval --accel dsa --benchmark payload-latency --device /dev/dsa/wq0.0 --iterations 3 --sizes 1048576,10485760,104857600,1073741824 --json --pin-core 0`

## Completion notes

The requested four payload sizes completed successfully. The run used three measured iterations per size to keep the 1 GiB row focused on the requested spot check rather than a long sweep.
