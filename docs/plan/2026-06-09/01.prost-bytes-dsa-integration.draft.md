# Prost bytes-field DSA encode integration draft

Status: draft

## Goal

Add an opt-in DSA path at Prost's protobuf `bytes` field encoding boundary.

The intended behavior is not generic Prost offload. CPU still encodes protobuf structure: field keys, varints, scalar fields, nested-message structure, and gRPC framing. DSA is used only for large `bytes` payload copies after the CPU has decided exactly where those payload bytes belong in the encoded output.

Target flow:

```text
message owned by encode future
  -> CPU encodes protobuf prefix / tags / lengths
  -> DSA copies selected large bytes fields into reserved output holes
  -> CPU continues encoding suffix fields
  -> future waits for all DSA completions
  -> tonic finishes compression / gRPC header / frame emission
```

## Current ground truth

- Generated Prost `Message::encode_raw` currently calls field helpers such as `prost::encoding::bytes::encode`.
- `prost::encoding::bytes::encode` writes the field key, writes the length varint, then appends the bytes value to the destination buffer.
- The `BytesAdapter` implementations differ in source ownership:
  - `bytes::Bytes` can be cloned cheaply and kept alive while hardware reads it.
  - `Vec<u8>` exposes a borrowed slice; using DSA without copying requires proving the message-owned vector remains alive and immutable until completion.
- `prost::transfer::{EncodeEngine, EncodeDst}` already gives us an owned encode-future boundary.
- `tonic-prost-async` already routes Prost encoding through that owned boundary with `CpuEngine`.
- Tonic's `EncodedBytes` keeps an `EncodeBuffer` owned while an encode future is pending and only writes the gRPC frame header after the future returns.
- `tonic-dsa-bytes-async` already proves the direct-DMA shape for one raw `Bytes` payload: owned source, owned Tonic encode buffer, pending DSA descriptor, page-fault retry, and drop-time completion draining.

## Design decision

Use a Prost field-transfer extension, not a hardware-specific generated struct and not a generic `BufMut::put` hack.

A DSA-aware `BufMut` alone is too blunt: it sees arbitrary byte writes, cannot reliably distinguish a protobuf `bytes` payload from strings or temporary buffers, and cannot safely make every borrowed source live across `Poll::Pending`. The clean seam is the generated bytes-field helper: generated code knows when a field is protobuf `bytes`, while the DSA implementation stays in an experimental codec crate.

## Proposed API shape

### 1. Add a field-aware Prost transfer trait

Keep the existing `prost::Message` API unchanged. Add a generated extension trait in `prost::transfer`, implemented by `prost-derive` alongside `Message`:

```rust
pub trait TransferMessage: Message {
    fn encode_transfer_raw<S>(&self, sink: &mut S) -> Result<(), S::Error>
    where
        S: EncodeSink;

    fn encode_transfer<S>(&self, sink: &mut S) -> Result<(), S::Error>
    where
        S: EncodeSink,
        S::Error: From<EncodeError>,
    {
        let required = self.encoded_len();
        let remaining = sink.remaining_mut();
        if required > remaining {
            return Err(EncodeError::new(required, remaining).into());
        }
        self.encode_transfer_raw(sink)
    }
}
```

The derive-generated transfer body mirrors `encode_raw`, except protobuf `bytes` fields call a sink method instead of directly calling `encoding::bytes::encode`:

```rust
sink.encode_bytes_field(tag, value)?;
```

All non-`bytes` fields keep using the existing CPU encoding helpers against the sink's `BufMut` implementation.

### 2. Add an `EncodeSink` hook for bytes fields

```rust
pub trait EncodeSink: bytes::BufMut {
    type Error;

    fn encode_bytes_field<B>(&mut self, tag: u32, value: &B) -> Result<(), Self::Error>
    where
        B: prost::encoding::BytesAdapter,
    {
        prost::encoding::bytes::encode(tag, value, self);
        Ok(())
    }
}
```

The default implementation preserves today's CPU behavior. A DSA sink overrides only `encode_bytes_field`.

### 3. Expose source classification without exposing hardware

Extend the sealed `BytesAdapter` internals with a small, hardware-neutral source view:

```rust
pub enum BytesSource<'a> {
    Shared(bytes::Bytes),
    Borrowed(&'a [u8]),
}
```

- `Bytes` returns `Shared(self.clone())`.
- `Vec<u8>` returns `Borrowed(self.as_slice())`.

The first DSA slice should accelerate only `Shared(Bytes)` sources. `Borrowed` / `Vec<u8>` stays on the CPU path unless we explicitly add a later invariant that the DSA future owns and pins the message until completion.

## DSA encode future

Add an experimental codec crate, preferably `tonic-prost-dsa-async`, so ordinary `tonic-prost` and `tonic-prost-async` remain CPU baselines.

The DSA encoder owns:

- the message being encoded,
- the Tonic `EncodeBuffer`,
- a shared DSA work queue,
- a threshold policy,
- pending field-copy descriptors and completion records.

First poll:

1. Compute `message.encoded_len()`.
2. Reserve the full encoded payload capacity in the destination before any descriptor is submitted. This is required so later CPU suffix writes cannot reallocate storage while DSA holds destination pointers.
3. Run `message.encode_transfer(...)` with a `DsaProstEncodeSink`.
4. For ordinary fields and small bytes fields, write with the CPU path.
5. For an eligible large `Bytes` field:
   - CPU writes the field key and length varint.
   - The sink reserves a private uninitialized hole in the Tonic encode buffer.
   - The sink advances the private buffer cursor so later CPU fields are written after the hole.
   - The sink submits a DSA memmove from the owned `Bytes` source into that hole.
   - The future stores the source, descriptor, completion record, destination pointer, length, and retry state.
6. If no descriptors were submitted, return `Ready(Ok(EncodeBuffer))`.
7. If descriptors are pending, return `Pending` and wake only through the DSA completion path.

Completion poll:

- Wait until every pending field copy reaches success.
- Reuse the existing page-fault retry policy from the async bytes crate: touch the reported fault page, adjust source/destination pointers by completed bytes, bound no-progress retries, and resubmit.
- On success, return the `EncodeBuffer` to Tonic.
- On selected DSA failure, return a `Status::internal` error. Do not silently CPU-fallback after hardware has been selected.
- On drop/cancellation, drain any submitted descriptors before dropping the message, sources, or destination buffer.

## Required Tonic buffer hook

The existing append-after-completion API is not enough for protobuf middle fields. A large bytes field can be followed by more fields, so the encoder needs to create a hole, continue writing after it, and only expose the final buffer after hardware has filled the hole.

Add a doc-hidden `EncodeBuf` API with narrow unsafe semantics, for example:

```rust
pub unsafe fn reserve_uninit_hole_for_pending(&mut self, len: usize) -> *mut u8;
```

Contract:

- The caller must have reserved enough total message capacity before retaining the pointer.
- The returned range is treated as private uninitialized storage until all DSA completions succeed.
- The buffer must not be read, split, compressed, framed, or exposed while any hole is pending.
- Error paths must not expose the buffer.
- Drop paths must drain submitted descriptors before freeing storage.

## Source policy

Initial policy:

- DSA-eligible: `bytes::Bytes` protobuf fields at or above the configured threshold.
- CPU-only: scalar fields, strings, nested structure, small `bytes` fields, and `Vec<u8>` bytes fields.

Reason: using DSA for `Vec<u8>` by first copying into an owned `Bytes` would add a CPU copy before the DSA copy and would not answer the intended question. Borrowed-vector DSA can be a later slice if we make the message-lifetime invariant explicit and test it.

## Implementation slices

1. Prost transfer surface:
   - Add `EncodeSink` and `TransferMessage` in `prost::transfer`.
   - Update `prost-derive` to emit `encode_transfer_raw`.
   - Add CPU parity tests proving `encode_transfer` produces exactly the same bytes as `Message::encode`.

2. Tonic private-hole support:
   - Add the doc-hidden reserve-hole API to `EncodeBuf`.
   - Cover the invariant with host-free tests: middle-field holes, suffix writes, no exposure before completion, and drop behavior.

3. DSA Prost codec:
   - Add `tonic-prost-dsa-async` as the opt-in experimental crate.
   - Reuse or move the DSA work-queue, retry, page-touch, and error-formatting logic from `tonic-dsa-bytes-async` without changing the CPU baseline crates.
   - Implement `DsaProstEncodeSink` and the owned pending encode future.

4. Completion waking:
   - Use a real completion registration path before performance claims. Repeated self-wake polling is acceptable only as a short correctness scaffold if it is removed before benchmarking.

5. Workload and benchmark:
   - Generate a test message with a large `bytes::Bytes` field, plus leading and trailing scalar fields to prove middle-hole correctness.
   - Compare standard `tonic-prost`, CPU `tonic-prost-async`, and DSA `tonic-prost-dsa-async` with the same payload bytes.

## Verification plan

Host-free tests:

- `TransferMessage::encode_transfer` byte-for-byte equals `Message::encode` for messages with no bytes fields, one bytes field, repeated bytes fields, nested messages, and leading/middle/trailing bytes fields.
- DSA sink leaves small bytes fields on CPU.
- DSA sink selects only `Bytes` sources, not `Vec<u8>` sources.
- Fake pending copy returns `Poll::Pending` before the frame is emitted.
- Suffix fields after a pending bytes field are preserved.
- DSA selection failure is returned as an error and does not CPU-fallback.
- Dropping a pending encode drains submitted descriptors.

Hardware checks through `launch`:

- Ignored DSA encode test for a large `Bytes` field.
- Page-fault retry smoke test using the same retry cases as the async bytes crate.
- End-to-end Tonic client/server benchmark for payload sizes around the known interesting range: 64 KiB, 1 MiB, 2 MiB, and 4 MiB.

Suggested commands once the slice exists:

```bash
rtk cargo test -p prost --test transfer
rtk cargo test -p prost-derive
rtk cargo test -p tonic-prost-async --lib
rtk cargo test -p tonic-prost-dsa-async --lib

rtk launch cargo test --manifest-path accel-rpc/tonic/Cargo.toml -p tonic-prost-dsa-async --test hardware_dsa -- --ignored
```

## Non-goals

- Do not offload full Prost encoding to DSA.
- Do not modify ordinary `tonic-prost` behavior.
- Do not require hardware for CPU parity tests.
- Do not claim a performance win from the implementation slice alone.
- Do not hide selected DSA failures behind CPU fallback.
- Do not optimize `Vec<u8>` bytes fields until the source-lifetime contract is explicit.

## Open risks

- The private-hole API is unsafe and load-bearing. Its tests must prove that Tonic never reads or frames the buffer until every pending field copy succeeds.
- A real completion wake path is still needed for performance-quality async behavior.
- The derive-generated transfer path increases Prost surface area. It should stay generic and hardware-neutral so the CPU path remains upstream-shaped.
