# Plan: Async Throughput Matrix Benchmark

## Goal

Add a small dsa-stdexec-style throughput benchmark entrypoint for the Rust async integration path so an operator can sweep message size and concurrency and get a CSV of measured async DSA throughput.

## Scope

In scope:

- Reuse the existing `tokio_memmove_bench --suite throughput` binary instead of adding another async execution implementation.
- Add a thin script under `idxd-rust/scripts/` that sweeps `bytes × concurrency`, runs the benchmark through the existing launcher-backed verifier path, and writes a CSV summary.
- Keep hardware truthfulness: hardware runs must still go through `devenv shell -- launch`, preserve raw/stdout/artifact files per point, and fail rather than silently falling back to software.
- Make the defaults small enough for quick prepared-host checks while allowing operators to override sizes, concurrency, duration, and output directory.
- Add host-free contract coverage for argument validation, CSV shape, and fake-binary aggregation.

Out of scope:

- Replacing `tokio_memmove_bench`.
- Adding a full dsa-stdexec benchmark framework in Rust.
- Changing async memmove runtime behavior or public APIs.
- Making performance claims from software diagnostics.

## Intended Changes

1. Add `idxd-rust/scripts/bench_async_throughput_matrix.sh` as a matrix wrapper over `tokio_memmove_bench --suite throughput`.
2. Emit one CSV row per matrix point with device, backend, bytes, concurrency, duration, completed/failed operation counts, ops/s, bytes/s, GiB/s, verdict, claim eligibility, and artifact paths.
3. Store each point's raw verifier output and JSON artifact in a stable output subdirectory.
4. Add a Rust contract test that runs the script with fake `devenv`, fake `getcap`, and a fake benchmark binary to prove the matrix aggregation without requiring hardware.
5. Run a small prepared-host hardware matrix on the shared DSA WQ after host-free tests pass.

## Verification

Host-free:

```bash

devenv shell -- cargo test --manifest-path ./Cargo.toml -p idxd-rust --test async_throughput_matrix_contract -- --nocapture
```

Prepared host:

```bash
IDXD_RUST_BENCH_DEVICE=/dev/dsa/wq0.1 \
IDXD_RUST_BENCH_BYTES=64,4096 \
IDXD_RUST_BENCH_CONCURRENCY=1,4 \
IDXD_RUST_BENCH_DURATION_MS=10 \
IDXD_RUST_BENCH_OUTPUT_DIR=target/async-throughput-matrix \
bash idxd-rust/scripts/bench_async_throughput_matrix.sh
```

## Outcome

Done. Added `idxd-rust/scripts/bench_async_throughput_matrix.sh`, a small dsa-stdexec-style matrix wrapper over the existing `tokio_memmove_bench --suite throughput` proof path. It builds the benchmark once, runs each bytes/concurrency point through `verify_tokio_memmove_bench.sh`, preserves per-point JSON/stdout/stderr/verifier logs, and emits `async_throughput_matrix.csv` with throughput and artifact-path columns.

Verified host-free with `bash -n idxd-rust/scripts/bench_async_throughput_matrix.sh` and `devenv shell -- cargo test --manifest-path ./Cargo.toml -p idxd-rust --test async_throughput_matrix_contract -- --nocapture` (2/2 tests passed). Verified on prepared hardware with `/dev/dsa/wq0.1`, bytes `64,4096`, concurrency `1,4`, duration `10ms`; all 4 hardware matrix points ended `ok=true`, `claim_eligible=true`, `verdict=pass`, and the CSV was written under `target/async-throughput-matrix/async_throughput_matrix.csv`.
