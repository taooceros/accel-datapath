# Poll-based async Prost encode plan

## Goal

Try a poll-based async Prost encoding API that preserves Prost's synchronous CPU behavior while allowing selected string and bytes payload copies to become asynchronous DSA work.

## Scope

- Add a poll-based message encoding surface beside the existing synchronous `Message::encode_raw` and the existing owned async encode boundary.
- Keep CPU/default behavior byte-for-byte equivalent to current Prost output.
- Keep DSA-specific selection, submission, completion, and failure handling inside the experimental DSA codec crate.
- Preserve Tonic framing/body state and use the existing owned encode future boundary from the async codec layer.
- Avoid boxed futures and dynamic dispatch in the Prost/Tonic async encode path.

## Intended changes

- Introduce a reusable poll-based state trait in `prost` so generated messages can resume after `Poll::Pending`.
- Generate compact per-message state for async-capable string/bytes fields, with small or non-accelerable fields delegated to synchronous encoding.
- Route generated string/bytes field encoding through poll helpers that let the sink choose CPU copy or async hardware copy.
- Refactor the experimental DSA Prost codec so its top-level encode future is a concrete state machine rather than `Pin<Box<dyn Future>>`.
- Extend tests to cover CPU equivalence and explicit pending/resume behavior.

## Verification

- Format and check the touched Prost and DSA crates.
- Run targeted generated async encode equivalence tests.
- Run DSA codec unit/integration tests.
- Run hardware smoke for large protobuf string/bytes fields through the async DSA path.

## Completion notes

- Added a poll-based `Message::poll_encode_raw` path backed by reusable `PollEncodeState` and an `EncodeRawAsync` future adapter. The default implementation delegates to synchronous `encode_raw`, so small/non-accelerable messages keep the CPU path.
- Generated encoders now override the poll path only when direct fields or maps can benefit from async string/bytes payload copies; message, group, oneof, and scalar-only fields are encoded synchronously.
- The DSA Prost codec now drives a concrete `DsaAsyncProstEncode<T>` state machine instead of a boxed dynamic future. DSA payload copy state remains inside `tonic-dsa-bytes-async`.
- Verified with `cargo check -p prost -p prost-derive`, `cargo check -p tonic-dsa-bytes-async`, full Prost tests, `tonic-prost-async` tests, `tonic-dsa-bytes-async` tests, `git diff --check`, and the ignored hardware DSA smoke through `launch`.
