# Prost async offload E2E test plan

## Goal

Add an end-to-end Prost test that proves generated messages can use the resumable async encode path, suspend and resume payload copies through `poll_put_payload`, and produce bytes identical to normal synchronous `prost::Message::encode`.

## Scope

- Work only in `accel-rpc/tonic/prost`.
- Add the test to `tests/src/message_encoding.rs` with local generated-message fixtures.
- Use a deterministic fake DSA/offload sink rather than real hardware.
- Do not change Tonic codec code.
- Keep `Message::encode_raw` synchronous and keep the Prost production path free of boxed futures or staging buffers.

## Intended changes

- Add generated test message types containing scalar fields, string/bytes payload fields, repeated payloads, map payloads, nested messages, and oneof payload/nested payload variants.
- Add a fake offload sink whose `poll_put_payload` stores owned payload state, returns `Pending`, and completes the copy only after resume.
- Assert async/offload encoded bytes exactly match synchronous Prost bytes and decode back to the original message.

## Completion notes

- Added local generated-message fixtures and `async_encode_e2e_fake_offload_resume_matches_sync_and_decodes` in `tests/src/message_encoding.rs`.
- The fake DSA sink stages each payload in owned state, forces `Poll::Pending`, verifies the resumed payload is the same suspended payload, then copies into the destination.
- The test asserts payload pending/completion counts, exact async-vs-sync byte equality, and normal Prost decode equality.
