# Prost DSA test ownership

## Goal
Move generated-Prost DSA payload-copy validation to the Prost test surface, and document the local crate responsibilities so future changes keep the dependency boundary clear.

## Scope
- Keep raw bytes DSA codec tests in `tonic-dsa-bytes-async`.
- Place generated protobuf encoding coverage under `prost/tests`.
- Add small crate-local `AGENTS.md` files for `prost/` and `tonic-dsa-bytes-async/`.
- Preserve opt-in hardware execution through the Prost `hardware-dsa` feature, `TONIC_DSA_WQ`, and `dsa_launcher` when direct access lacks capability.

## Intended changes
- Remove generated-message shape coverage from the DSA bytes crate hardware test file.
- Add the generated-message DSA e2e hardware coverage to Prost tests.
- Add any test-only dependency wiring needed for Prost tests to drive a DSA-backed async payload sink.
- Keep Tonic codec plumbing unchanged.

## Verification
- Run the targeted Prost async/protobuf encoding tests.
- Run the async DSA crate tests to ensure raw bytes DSA coverage still passes.
- Run the hardware protobuf encoding test through the DSA launcher when direct access is not permitted.
