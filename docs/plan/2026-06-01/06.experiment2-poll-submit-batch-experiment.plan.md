# Experiment 2 poll-submit-batch experiment plan

## Goal

Conduct the Experiment 2 mechanism probe that varies how many descriptor submissions occur between poll events. Here `poll_submit_batch_n` means submitted logical requests between polls, not DSA batch descriptors and not number of completion records read in a poll scan.

## Scope

- Add a focused mechanism-probe axis for `poll_submit_batch_n`.
- Preserve the existing baseline mechanism rows and result family.
- Run a focused hardware experiment through `launch` with release `hw-eval`.
- Record the results under `docs/report/benchmarking/`.

## Intended changes

- Add CLI/config support for `--marker-poll-submit-batches`.
- Add `poll_submit_batch_n` to `submit_marker_mechanism` result rows.
- Emit `poll-submit-batch` mechanism rows for configured values beyond the baseline value `1`.
- Use `n=160`, `poll_offset=1`, `noop`, and a focused batch sweep for the first hardware run.

## Verification

- Run targeted Experiment 2 tests and the full `hw-eval` test suite.
- Build `hw-eval` in release mode.
- Run the hardware benchmark through `launch`, not by direct execution.
- Validate the JSON has the expected batch rows, no missing completions/errors, and interpretable poll latency metrics.
