# Experiment 2 configuration-suite plan

## Goal

Turn Experiment 2 from a single traced-overlap view into the default configuration suite for explaining why completions become visible after only a few traced submit/poll iterations while Experiment 1 reaches submit-admission backpressure around 116--117 outstanding operations.

## Research question

Experiment 1 measures a submit-credit/admission window. Experiment 2 measures completion visibility after elapsed submit/poll time. The next Experiment 2 runs should separate these effects:

1. How much elapsed TSC time has passed when a completion first becomes visible?
2. Does the answer move when polling starts early versus near the Experiment 1 admission wall?
3. Is the expensive status read caused by completion-record cacheline ownership/visibility, or by the submit path itself?
4. Do layout, prefetch, cache state, and timing method change the visible-read cost?

## Configuration dimensions

Use the existing Experiment 2 knobs and mechanism probes rather than creating another benchmark family:

- Baseline overlap trace: `submit_marker_overlap` rows.
- Mechanism probes: `submit_marker_mechanism` rows for packed baseline, padded layout, prefetch distances, batch-scan timing, pre-touch, and clflush.
- Burst length `N`: keep `160` as the focused default for direct comparison with the current traces; sweep `128` and `256` when testing sensitivity around and beyond the Experiment 1 knee.
- Poll offsets: include early offsets such as `1,8,10,12` to resolve the completion-visible frontier, and near-wall offsets such as `96,112,115` to compare against the Experiment 1 credit knee.
- Marker position: use `first` for the primary causal trace; use `half,last` as controls when checking whether visibility is marker-relative or just elapsed-time relative.
- Operation class: start with `noop`; rerun `memmove64` only if the submit/visibility relationship changes unexpectedly.

## Intended code change

Make the normal Experiment 2 selector, `--benchmark submit-marker-overlap`, run the complete Experiment 2 suite by default:

1. Emit the baseline `submit_marker_overlap` trace rows for the configured marker bursts, positions, and poll offsets.
2. Emit all `submit_marker_mechanism` probe rows for the same marker bursts and poll offsets.
3. Keep `--benchmark submit-marker-mechanism` available as the mechanism-only selector for surgical reruns.
4. Preserve existing JSON row names and fields; the default Experiment 2 run only adds the mechanism result family to the same report.
