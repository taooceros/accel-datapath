# Experiment 1 codepath cleanup plan

## Goal

Make Experiment 1 (`submit-occupancy`) understandable after adding trace mode. The code should read as one experiment with two result modes: summary one-extra mode and raw trace mode.

## Scope

- Refactor only `hw-eval/src/benchmarks/submission_bottleneck/experiment_1_submit_occupancy.rs` unless JSON field names force a small companion change.
- Preserve the existing CLI and JSON shape:
  - normal mode emits summary `submit_occupancy` rows;
  - `--submit-occupancy-trace-until` emits raw `extra_submit_trace` and `trace_outcomes` in `submit_occupancy` rows.
- Keep all allocations outside the measured submit loop.
- Keep the sentinel drain descriptor valid after struct moves.

## Intended changes

- Introduce explicit local concepts for the experiment:
  - case/mode selection;
  - shared scratch state;
  - one function for a summary case;
  - one function for a trace case;
  - small helpers for timing one submit and recording cleanup outcome.
- Remove duplicated reset/prefill/drain logic from each mode.
- Keep code close to Experiment 2 style: scratch owns reusable state, per-case functions return result rows, printing is separate.

## Verification

- `cargo fmt -p hw-eval`
- `cargo build --release -p hw-eval`
- focused config tests
- launch smoke for one-extra summary mode
- launch smoke for trace mode

## Completion notes

Completed. Experiment 1 is now a straight-line raw trace collector: for each K it resets completions, submits the K prefill descriptors, times submit indexes `K..trace_until`, drains with a sentinel, and records `extra_submit_trace` plus `trace_outcomes`. The former summary/statistics case and helper abstractions were removed. Default mode records exactly one measured submit per iteration (`trace_until = K + 1`); `--submit-occupancy-trace-until` widens the measured range. Post-processing owns medians, p95, and plots.
