# Separate DSA sync Prost encode crate

## Goal

Move the first Tonic/Prost DSA integration slice into a separate experimental crate named `tonic-prost-dsa-sync`. The initial implementation targets the encode path only: Prost encodes into a staging buffer, then a synchronous DSA memmove copies the encoded protobuf payload into tonic's output buffer while the caller polls/spins for completion.

## Scope

- Add `tonic-prost-dsa-sync` as a workspace member.
- Keep `tonic-prost` and its `ProstCodec` / `ProstEncoder` as the CPU-only baseline.
- Make DSA support unconditional inside the new experimental crate instead of requiring a feature flag.
- Use a shared DSA work queue handle for DSA encoders instead of taking an `RwLock` on every encode.
- Reuse the existing `tonic_prost::ProstDecoder` for decode.
- Preserve process-wide DSA initialization helpers for experiment setup: device path plus minimum message size.
- Keep hardware optional for unit tests by covering configuration failure, CPU behavior without a work queue, CPU-baseline isolation, and shared-handle thread-safety bounds.

## Non-goals

- Do not add async DSA completion into Tonic's body state machine in this slice.
- Do not modify generated service code by default; generated services can opt into the codec through `codec_path = "tonic_prost_dsa_sync::DsaSyncProstCodec"`.
- Do not hide selected DSA failures behind CPU fallback.
- Do not claim a performance result from this implementation.

## Verification

- Run focused tests for `tonic-prost-dsa-sync`.
- Run focused tests/checks for `tonic-prost` to keep the CPU baseline healthy.
- Run package checks for the new crate.
- Run a diff whitespace check.

## Completion notes

Implemented `tonic-prost-dsa-sync` as a separate workspace crate. The crate exports `DsaSyncProstCodec`, `DsaSyncProstEncoder`, `DsaWorkQueue`, `SharedDsaWorkQueue`, and process-wide DSA initialization helpers. Encode uses Prost staging plus a synchronous DSA memmove into tonic output spare capacity; decode reuses `tonic_prost::ProstDecoder`. The normal `tonic-prost` codec remains the CPU baseline.

The DSA hot path no longer reads a process `RwLock`. A shared `Arc<DsaWorkQueue>` is cloned when codecs/encoders are constructed and borrowed during encode; the process default is installed once through runtime-input initialization. This matches the shared-WQ research assumption and keeps per-message selection to a local `Option` check plus threshold comparison.

Verification completed from `accel-rpc/tonic`: `cargo test -p tonic-prost-dsa-sync --lib`, `cargo check -p tonic-prost-dsa-sync`, `cargo test -p tonic-prost --lib`, `cargo check -p tonic-prost`, `cargo test -p tonic --lib`, and `git diff --check`. Root `git diff --check` also passed for the original separate-crate slice.
