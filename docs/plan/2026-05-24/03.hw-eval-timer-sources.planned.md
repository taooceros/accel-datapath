# hw-eval timer-source measurements

## Goal

Extend the DSA submit-only study so the same benchmark records three independent timing signals:

- wall-clock elapsed nanoseconds;
- invariant TSC ticks via `rdtscp`;
- actual unhalted core cycles via PMU (`perf_event_open`, `PERF_COUNT_HW_CPU_CYCLES`).

The purpose is to avoid conflating invariant TSC ticks with current-core cycles after CPU governor changes showed large shifts in measured TSC deltas.

## Scope

Code changes stay inside `hw-eval` and should be generic enough for future latency benchmarks, while only the DSA submit-only family needs to use all timers in this pass.

## Design

Add a small timer abstraction in `hw-eval/src/submit.rs`:

- `WallClockTimer`: uses `Instant` and reports elapsed nanoseconds.
- `TscTimer`: uses `lfence` + `rdtscp` and reports TSC ticks.
- `PmuCycleTimer`: uses `perf_event_open` for current-thread `PERF_COUNT_HW_CPU_CYCLES` and reports unhalted core cycles.
- `TimerSample`: holds the three optional values for one measured region.
- `MeasurementTimers`: owns optional PMU state and samples all three signals around a closure.

The hot region should have exactly one start and one stop per burst, not per submission. PMU setup happens once per benchmark process; per-sample PMU operations use ioctl reset/enable/disable plus one read. That overhead is acceptable for the first research pass and can be calibrated later with an empty workload if needed.

## JSON compatibility

Preserve existing fields:

- `cycles`: keep as TSC ticks for compatibility;
- `ns`: switch submit-only rows to wall-clock nanoseconds rather than TSC-derived nanoseconds.

Add optional fields to `LatencyResult`:

- `tsc_ticks`: duplicate TSC stats with a correct name for new consumers;
- `wall_ns`: duplicate wall-clock stats with a correct name;
- `core_cycles`: PMU unhalted core-cycle stats when available.

Existing benchmarks can leave these optional fields absent until migrated.

## Error behavior

PMU may be unavailable because of kernel policy (`perf_event_paranoid`) or permissions. The benchmark should not fail by default. It should:

- try to open PMU cycles once;
- if unavailable, print a warning in text mode;
- in JSON mode, omit `core_cycles`.

## Verification

- `cargo fmt --package hw-eval`
- `cargo test -p hw-eval`
- `cargo build --release -p hw-eval`
- hardware run through `launch`:

```bash
launch ./target/release/hw-eval --accel dsa --benchmark submit-only --submit-mode unloaded --device /dev/dsa/wq0.0 --json --iterations 1000 --sizes 64 --pin-core 0
```

Then inspect that submit-only rows include `tsc_ticks`, `wall_ns`, and, if permissions allow, `core_cycles`.
