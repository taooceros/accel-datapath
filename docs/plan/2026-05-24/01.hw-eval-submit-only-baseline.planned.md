# hw-eval submit-only baseline plan

## Goal

Add a DSA hardware benchmark row that isolates the portal submission instruction cost from descriptor setup and completion polling as much as the current `hw-eval` harness allows.

## Scope

- Add a DSA-only submit-only baseline to `hw-eval`.
- Time a tight burst of repeated submissions of one prebuilt NOOP descriptor.
- Report submissions/sec in the existing JSON throughput list so existing artifact tooling can consume it.
- Keep existing latency and throughput rows compatible.

## Intended measurement shape

- Build one NOOP descriptor and completion record before timing.
- For each tested burst size, reset only the completion record outside the timed region.
- Time only a loop of `wq.submit(&desc)` repeated `burst_size` times.
- Drain after timing so descriptor and completion storage remain valid until hardware has observed the submitted work.
- Use `max_concurrency` as the cap for tested burst sizes.

## Non-goals

- This does not prove operation completion latency.
- This does not measure descriptor fill, completion polling, or payload DMA.
- This does not make shared-WQ ENQCMD retry cost invisible; shared-WQ results still include accepted/retry behavior inside `submit_desc64`.

## Verification

- Run the focused `hw-eval` test/build path that catches Rust type and CLI/report compatibility issues.
- Do not run hardware-facing commands directly; live hardware validation must use `launch` or `dsa_launcher` separately.
