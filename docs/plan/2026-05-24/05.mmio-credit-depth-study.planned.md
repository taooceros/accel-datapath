# MMIO credit-depth study

## Goal

Frame a focused experiment that separates the different limits hidden behind “MMIO credits” in the current DSA submit-only measurements.

The immediate question is: when unordered/fenceless MMIO submissions are issued as fast as possible, how many requests can be absorbed before the issuing core observes backpressure?

## Hypothesis

The current knee near burst 128 is probably the DSA dedicated work-queue depth, not the raw PCIe posted-write credit pool.

For `/dev/dsa/wq0.0`, sysfs reports:

```text
/sys/bus/dsa/devices/wq0.0/size = 128
/sys/bus/dsa/devices/wq0.0/mode = dedicated
```

The observed unloaded same-descriptor submit-only data stays cheap through burst 64 and jumps at burst 128. That lines up with WQ admission credits.

## Limits to separate

A fenceless 64-byte MMIO submit can be limited by several queues in series:

1. CPU store-side buffers / write-combining behavior.
2. Root-complex posted-write buffering.
3. PCIe posted header/data credits.
4. Device BAR ingress buffering.
5. DSA work-queue descriptor slots.

The current benchmark primarily exposes item 5. It does not directly measure raw PCIe posted-write credits because every write is a semantically meaningful DSA descriptor submission to a finite WQ.

## Experiment design

### Experiment A: WQ-depth correlation

Run the existing submit-only benchmark against dedicated WQs with different configured `size` values, if available or reconfigurable.

Command shape:

```bash
launch ./target/release/hw-eval \
  --accel dsa \
  --benchmark submit-only \
  --submit-mode unloaded \
  --device /dev/dsa/wqX.Y \
  --json \
  --iterations 1000 \
  --sizes 64 \
  --submit-bursts 32,64,96,112,120,124,128,132,136,144,160,192,256 \
  --pin-core 0
```

Expected result if the knee is WQ depth:

- The first sharp latency jump tracks `wq.size`.
- A WQ with size 64 should jump near 64.
- A WQ with size 128 should jump near 128.

### Experiment B: knee refinement around 128

Use dense burst points around the suspected knee on the current WQ.

```bash
launch ./target/release/hw-eval \
  --accel dsa \
  --benchmark submit-only \
  --submit-mode unloaded \
  --device /dev/dsa/wq0.0 \
  --json \
  --iterations 3000 \
  --sizes 64 \
  --submit-bursts 96,104,112,120,124,126,127,128,129,130,132,136,144,160 \
  --pin-core 0
```

Use TSC, wall, and RDPMC. Ignore ioctl-PMU for the knee itself except as a control.

Expected result:

- If WQ credit is the first bottleneck, burst 127 should remain close to the cheap regime and burst 128/129 should show a clear admission stall.
- If the knee starts earlier and gradually, then CPU/root-complex/device buffering is interacting with WQ admission rather than a single hard slot count.

### Experiment C: single-burst pressure-ramp runs

Run `--submit-mode sustained` with one burst point per process, using `--submit-bursts <N>`, so each process starts from a comparable queue state.

Example:

```bash
launch ./target/release/hw-eval \
  --accel dsa \
  --benchmark submit-only \
  --submit-mode sustained \
  --device /dev/dsa/wq0.0 \
  --json \
  --iterations 1000 \
  --sizes 64 \
  --submit-bursts 128 \
  --pin-core 0
```

Repeat for `N = 64,96,112,120,124,128,132,144,160,192,256`.

Expected result:

- This tests sustained admission behavior without cross-burst contamination inside one process.
- RDPMC should show the core-cycle cost once backpressure is established.

### Experiment D: raw MMIO sink later

To approximate the Utah paper’s pure unordered-MMIO payload question, DSA is the wrong target because WQ admission is semantic and finite. A later experiment should use a BAR region where repeated 64-byte stores do not allocate finite descriptor slots, or a controllable device/FPGA endpoint that accepts posted writes into a sink buffer.

That would test raw posted-write credit depth more directly. The DSA submit-only benchmark remains valuable as a real-device admission benchmark.

## Metrics to report

For each burst and timer:

- median batch latency;
- per-submit median (`median / burst`);
- calibrated median (`median - submit_only_empty median`);
- knee location: first burst where calibrated median exceeds a chosen multiplier over the cheap-regime median;
- RDPMC vs TSC/wall consistency.

## Interpretation rules

- Treat `submit_only_unloaded` as queue-admission capacity under fenceless issue.
- Treat `submit_only_pressure_ramp` as a stateful backpressure trajectory, not an independent per-burst table.
- Use RDPMC for core-cycle attribution after empty calibration.
- Use TSC and wall as elapsed-time cross-checks.
- Do not claim raw PCIe posted-credit depth from DSA WQ results unless WQ depth is ruled out.

## Completion criteria

This experiment frame is complete when we can answer:

1. Does the first knee track `wq.size`?
2. Is the 128-descriptor knee sharp or gradual?
3. How many fenceless DSA submissions can be issued before observable admission backpressure on this WQ?
4. What additional non-DSA endpoint would be required to measure raw unordered MMIO posted-write credit depth?

## Completion notes

Implemented the first admission probe as `--benchmark submit-admission`. It submits distinct completion-bearing NOOP descriptors without software inflight gating and reports completed/missing/error counts plus submit-loop timing. On `/dev/dsa/wq0.0`, every descriptor completed with zero missing completions up to burst 1024, while submit latency increased beyond the WQ depth. For this platform, over-depth dedicated-WQ `movdir64b` behaves as backpressured/admission-paced in this probe rather than silently lost.
