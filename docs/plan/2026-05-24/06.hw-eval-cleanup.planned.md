# hw-eval cleanup plan

Status: completed
Date: 2026-05-24

## Goal

Clean up the recent `hw-eval` benchmarking code without changing CLI behavior, JSON schema, or hardware measurement semantics.

## Scope

Focus on small behavior-preserving refactors in the benchmark support code that now carries the most accidental complexity:

- `hw-eval/src/config.rs`
- `hw-eval/src/main.rs`
- `hw-eval/src/report.rs`
- `hw-eval/src/methodology/dsa.rs`

The cleanup will not redesign benchmark families, change benchmark labels, add dependencies, or reconfigure hardware.

## Inspection findings

- The comma-list parser allocates the raw input eagerly even though successful parsing is the common path.
- Report constructors encode legacy JSON compatibility rules in three separate places.
- Top-level report metadata construction is mixed into report assembly.
- The submit-admission probe has duplicated completion scanning and a shadowed `outcome`, making the bounded-wait/drain/rescan sequence harder to audit.
- Submit-only workload constants and timer sequencing are correct but slightly scattered.

## Completed changes

1. Made comma-list parsing allocate the raw input only on error while preserving the same error variants, display text, and source chaining.
2. Centralized submit-timer `LatencyResult` row construction so the legacy `cycles`/`ns` aliases remain explicit and tested.
3. Kept report metadata inline in `build_report`; extracting it was not worth an extra single-use helper.
4. Routed CLI normalization through the method-level `bon` builder instead of suppressing the release-only unused-builder warning.
5. Clarified submit-only workload constants and the admission completion scan flow without changing timing regions, labels, or drain behavior.
6. Added a focused test for submit-timer legacy alias fields.

## Verification

Observed focused checks:

```bash
cargo fmt --package hw-eval
cargo test -p hw-eval
cargo build --release -p hw-eval
```

Results:

- `cargo test -p hw-eval`: 24 tests passed.
- `cargo build --release -p hw-eval`: passed.

No hardware run was needed because the cleanup is structural and does not make a new performance claim.
