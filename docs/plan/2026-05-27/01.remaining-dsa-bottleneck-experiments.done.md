# Remaining DSA bottleneck experiments implementation plan

## Goal

Finish the `hw-eval` runner support needed for the remaining DSA submission-bottleneck experiments in `docs/plan/2026-05-26/02.dsa-submission-bottleneck-experiment.plan.md`.

The implementation should keep the experiment code clean, explicit, and easy to find near the existing bottleneck runner in `hw-eval/src/methodology/submission_bottleneck.rs`.

## Scope

Implement runner and JSON support for:

1. Experiment 2: marker completion overlap during submit.
2. Experiment 3: traffic-class isolation ladder.
3. Experiment 4: completion handling and reuse policy.

Keep Experiment 5 as the existing `submit-admission` correctness gate unless implementation work changes descriptor lifetime, completion layout, or blind-push behavior enough to require an additional compatibility wrapper.

## Intended changes

- Add explicit CLI selectors for each new experiment rather than overloading existing benchmark modes.
- Add only the parsing knobs required by the experiments: marker burst lengths/positions/poll cadence, ladder windows/traffic class, and completion policy/window knobs.
- Add top-level JSON arrays for the new result families so reports do not need to parse stdout.
- Reuse the existing DSA descriptor/completion helpers and the first bottleneck runner's operation constructor pattern.
- Preserve existing `submit-only`, `submit-admission`, `submit-occupancy`, DSA, IAX, and software-only behavior.

## Verification plan

After implementation, run only claim-scoped checks:

- targeted `hw-eval` config unit tests for new parser/default/invalid-combination behavior;
- targeted CLI contract tests for the new DSA-only selectors and JSON report shape;
- `cargo build --release -p hw-eval` before any hardware run;
- hardware smoke runs through `launch ./target/release/hw-eval`, not direct binary execution, one minimal run per new selector.

Full experiment sweeps and presentation/report updates happen after the selectors smoke successfully.
