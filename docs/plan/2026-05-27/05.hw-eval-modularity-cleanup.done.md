# hw-eval modularity cleanup plan

## Goal
Make the `hw-eval` submission-bottleneck experiment workflow easier to navigate after the experiment expansion by aligning module names, modern Rust module layout, dispatch boundaries, and result/config plumbing.

## Scope
- Keep the existing benchmark selectors and JSON field names stable.
- Convert the remaining methodology module root away from `mod.rs`.
- Align Experiment 5 naming with the existing `submit-admission` probe instead of introducing a duplicate selector.
- Move submission-bottleneck dispatch behind the `submission_bottleneck` module root.
- Group submission-bottleneck configuration and result vectors internally so `main` and `methodology::dsa` stop passing long positional argument lists.
- Split the completion-reuse experiment policy state machines into named helpers.
- Update README structure notes so a maintainer can find the actual execution path.

## Non-goals
- Do not change measured benchmark semantics.
- Do not change hardware-facing CLI selectors.
- Do not change top-level JSON keys; preserve the current report contract.
- Do not run hardware benchmarks for this structural cleanup.

## Changes made
- Replaced `hw-eval/src/methodology/mod.rs` with `hw-eval/src/methodology.rs`.
- Renamed Experiment 5 from `experiment_5_blind_push_correctness` to `experiment_5_submit_admission_probe` while keeping it as the existing `submit-admission` correctness gate.
- Added `SubmissionBottleneckConfig` to group experiment-specific normalized config.
- Added `SubmissionBottleneckResults` to group internal result vectors while preserving top-level JSON keys.
- Replaced the wide DSA benchmark function signature with `DsaBenchmarkRequest` and `DsaBenchmarkResults`.
- Moved submission-bottleneck selector dispatch behind `submission_bottleneck::run`.
- Split Experiment 4 completion-reuse policy control flow into named policy helpers.
- Moved DSA operation/traffic sizing semantics out of `config.rs` and into submission-bottleneck helper code.
- Updated `hw-eval/README.md` structure and bottleneck report documentation.
