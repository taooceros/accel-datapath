# Submit marker cumulative trace

## Goal
Use Experiment 2 trace output to explain the cumulative elapsed time from marker submit start to first observed completion. Per-operation submit and poll slices are not enough to attribute the wall-clock interval; the trace needs cumulative offsets from the marker submit.

## Intended change
Each trace point will include optional TSC statistics for submit start, submit end, and poll end relative to the marker submit start. These fields are populated after the marker descriptor has been submitted. Existing submit and poll latency fields remain unchanged.

## Verification
Build in release, rerun offset-1 one-poll hardware data, and confirm the cumulative poll-end value at first success matches the row-level marker-visible latency.

## Completion notes
The cumulative trace shows the 1174--1230 tick interval is not explained by submit and poll slices alone. For the offset-1 one-poll rerun, first median visibility occurred at submit index 8 with about 228 ticks of measured submit slices, about 386 ticks of measured poll slices, about 286 ticks of inter-iteration gap, and the rest in submit-end-to-poll-end overhead captured by cumulative poll-end timing.
