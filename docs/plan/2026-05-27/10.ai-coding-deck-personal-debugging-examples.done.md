### Slide: `06 · PERSONAL TRACE` / `The alignment bug was painful—and useful`

Purpose: show the opposite pattern: debugging struggle built reusable judgment about hardware/language boundaries.

Takeaway: the coroutine alignment bug forced a durable model: DSA has descriptor/completion alignment requirements, and coroutine-frame allocation can break naive `alignas()` assumptions.

Visible components:

- Top line: `The useful struggle was finding the wrong abstraction boundary.`
- A cause chain:
  - `hardware invariant` / `64-byte descriptor; 32-byte completion record`
  - `language trap` / `coroutine frame allocation may not honor member over-alignment`
  - `fix` / `over-allocate, compute aligned pointers once, cache them`
- A small code-shaped formula: `(base + align - 1) & ~(align - 1)`.
- Reflection band: `After this, I could review similar async/hardware code instead of only trusting the generated fix.`

Visual guidance: use three columns or a compact pipeline. This slide should feel like a debugging story, not a hardware spec table.
