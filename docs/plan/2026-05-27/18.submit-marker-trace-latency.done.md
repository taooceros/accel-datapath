# Submit-marker traced latency plan

## Goal

Rewrite the DSA submission-bottleneck experiment 2 measurement so it answers whether early descriptors are completing before the submit-admission wall near request 115, while also preserving a per-submit latency trace that can be plotted.

## Scope

- Keep the existing `submit-marker-overlap` selector name so callers do not need a new benchmark selector.
- Replace cadence/fraction-oriented output with a traced active-observation row: after a configurable poll offset, every later submit records its own submit latency plus timed polls of a small completion prefix.
- Add a CLI option for marker poll offsets; keep old marker poll cadence parsing accepted only for compatibility if needed.
- Serialize a list of trace points, one per measured submit index, so plotting can use the submit-index axis directly.
- Update the README and targeted CLI/config tests for the new schema knob.

## Non-goals

- Do not add DSA hardware batch descriptors.
- Do not add a broader benchmark framework.
- Do not claim performance conclusions without a launch-backed hardware run.

## Verification

- Format the `hw-eval` crate.
- Run targeted `hw-eval` config/CLI tests covering the new option and selector parsing.
- Build the release binary.
- Run a minimal launch smoke for `submit-marker-overlap` if the configured DSA WQ is available.
