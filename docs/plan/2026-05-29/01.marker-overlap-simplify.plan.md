# Simplify marker overlap benchmark code

## Goal

Make `hw-eval/src/benchmarks/submission_bottleneck/experiment_2_marker_overlap.rs` easier to read without changing benchmark behavior, JSON shape, or measurement semantics.

## Scope

- Keep the benchmark selector and result fields stable.
- Preserve the traced submit/poll loop semantics.
- Prefer local helper extraction and simpler data flow over broad rewrites.
- Do not add new measurement behavior.

## Intended changes

- Consolidate repeated marker-relative timing calculations.
- Add a small `measured_call` wrapper for TSC-bracketed operations.
- Make per-submit trace recording a single clear operation.
- Keep accumulator conversion and result assembly explicit.

## Completion notes

Added a local `SubmitTiming` value object for submit-duration and marker-relative timing calculations, a local `measured_call` wrapper for submit and completion-status reads, unified trace/sample recording around those helpers, and moved repeated poll-result projections into `CompletionPollResult` methods. No result fields or measurement flow were intentionally changed.
