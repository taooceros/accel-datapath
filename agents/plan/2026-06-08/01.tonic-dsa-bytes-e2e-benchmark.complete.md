# Agent plan: Tonic DSA mock bytes RPC throughput benchmark

## Goal

Implement, verify, measure, and profile a standalone executable comparing standard raw bytes transfer against `tonic-dsa-bytes-sync` over a real Tonic mock bytes RPC path.

## Completed work

- Inspected the existing synchronous DSA raw bytes codec and isolated encoder benchmark.
- Implemented `tonic-dsa-bytes-sync/src/bin/mock_bytes_rpc_throughput.rs`.
- The executable includes a minimal standard raw bytes codec baseline, a manual Tonic unary echo service, client setup, payload validation, concurrent warmup, timed concurrent request loop, and CSV output.
- The benchmark uses `TcpIncoming` with `TCP_NODELAY`, Tonic `Channel` clones, and per-row server shutdown.
- DSA runs are opt-in via `TONIC_DSA_WQ` or `--dsa-wq`; hardware runs require `launch` for `CAP_SYS_RAWIO`.
- Added `--dsa-min-message-bytes` to test threshold policies and keep small payloads on CPU.
- Updated `tonic-dsa-bytes-sync/Cargo.toml` with the executable's required dependencies and Tonic features.

## Verification and measurement

Observed locally from `accel-rpc/tonic` unless noted:

```bash
cargo fmt -p tonic-dsa-bytes-sync
cargo check -p tonic-dsa-bytes-sync --bin mock_bytes_rpc_throughput
cargo check -p tonic-dsa-bytes-sync --benches
cargo build --release -p tonic-dsa-bytes-sync --bin mock_bytes_rpc_throughput
```

Observed from repo root:

```bash
launch accel-rpc/tonic/target/release/mock_bytes_rpc_throughput --codec both --requests 5000 --concurrency 64 --warmup 256 --dsa-wq /dev/dsa/wq0.0
TONIC_DSA_WQ=/dev/dsa/wq0.0 launch bash -lc 'cd accel-rpc/tonic && cargo bench -p tonic-dsa-bytes-sync --bench buf_codec'
launch perf record -F 199 -g -o /tmp/tonic-standard-64.perf.data -- accel-rpc/tonic/target/release/mock_bytes_rpc_throughput --codec standard --payload-bytes 64 --requests 100000 --concurrency 64 --warmup 2048
launch perf record -F 199 -g -o /tmp/tonic-dsa-64.perf.data -- accel-rpc/tonic/target/release/mock_bytes_rpc_throughput --codec dsa --payload-bytes 64 --requests 100000 --concurrency 64 --warmup 2048 --dsa-min-message-bytes 1 --dsa-wq /dev/dsa/wq0.0
```

The hardware throughput report is `docs/report/benchmarking/053.tonic_mock_bytes_rpc_throughput_2026-06-08.md`. Current evidence: isolated DSA copy is slower through 1 MiB; e2e DSA benefits are noisy below 1 MiB and more plausible around 2–4 MiB.
