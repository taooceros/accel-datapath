# Agent plan: direct EncodeBuf async DSA copy

## Goal

Change the async DSA bytes encoder from staged destination bytes to direct DSA writes into Tonic's encode buffer under the explicit stable-buffer experiment assumption.

## Constraints

- Keep the CPU fallback unchanged.
- Keep pending DSA descriptor/completion/source storage alive until terminal hardware completion, including drop/cancellation paths.
- Add only a low-level doc-hidden `EncodeBuf` API for delayed commit; do not expose a polished public abstraction yet.
- Update benchmark/report notes so they no longer claim the async path has a staging buffer.

## Steps

1. Add unsafe delayed reserve/advance helpers to `EncodeBuf` plus tests.
2. Thread a stable-buffer flag through `EncodeBody` in-flight state so buffered prefixes are not split while a direct pointer is outstanding.
3. Rewrite `tonic-dsa-bytes-async` pending DSA state to store a destination pointer and advance the final buffer on completion.
4. Update hardware smoke tests and benchmark report/plans.
5. Run formatting, targeted async checks, neutral benchmark checks, and hardware smoke/performance runs through `launch`.

## Completed work

- Added delayed pending-reservation APIs to `EncodeBuf`.
- Added a stable-buffer marker to Tonic's in-flight encode state to avoid splitting the underlying encode buffer while a direct reservation is outstanding.
- Rewrote async DSA pending copy to write directly into final encode buffer storage and advance it on successful DSA completion.
- Verified async hardware smoke and direct-buffer benchmark runs through `launch`.
- Updated `docs/report/benchmarking/054.async_sync_standard_bytes_rpc_2026-06-08.md` with direct-buffer results.

## Result

Direct async DSA is now performance-relevant. It won the observed 64 KiB rows in both direct reruns and the 1 MiB / 2 MiB rows in the broader sweep. Sync DSA still wins some regimes, especially 4 KiB and 4 MiB in the observed broad sweep.
