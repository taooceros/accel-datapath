# Agent plan: async DSA bytes transfer crate

## Goal

Implement and verify a new `tonic-dsa-bytes-async` crate that exercises Tonic's `poll_encode` interface with explicit asynchronous DSA copy state.

## Constraints

- Keep DSA details out of `tonic` and `tonic-prost`.
- Keep CPU behavior as the fallback/default when no work queue is configured.
- Do not retain an `EncodeBuf` spare-capacity pointer across `Poll::Pending`; use staged output unless Tonic exposes a safe delayed-advance API.
- Keep all pending hardware storage alive until completion, including cancellation/drop paths.

## Steps

1. Add the crate manifest and source under `accel-rpc/tonic/tonic-dsa-bytes-async`.
2. Add the crate to the `accel-rpc/tonic` workspace members.
3. Implement config, work-queue opening, async bytes codec, encoder, decoder, and pinned pending DSA copy state.
4. Add tests for CPU fallback and pending encode behavior.
5. Run formatter, targeted tests, and targeted check from `accel-rpc/tonic`.

## Completed work

- Added `tonic-dsa-bytes-async` with a raw `Bytes`/`Bytes` codec.
- Wired the crate into `accel-rpc/tonic/Cargo.toml`.
- Implemented async DSA encode state using `poll_encode`, heap-pinned descriptor/completion storage, cloned `Bytes` source ownership, direct final encode-buffer destination storage, and drop-time drain for submitted operations.
- Preserved CPU fallback when no work queue is configured.
- Added tests for codec construction, CPU fallback through `EncodeBody`, deterministic pending encode through `EncodeBody`, and an ignored hardware DSA smoke path.
- Verified with `rtk cargo fmt -p tonic-dsa-bytes-async -- --check`, `rtk cargo test -p tonic-dsa-bytes-async`, `rtk cargo check -p tonic-dsa-bytes-async`, `rtk cargo clippy -p tonic-dsa-bytes-async --all-targets --no-deps -- -D warnings`, `rtk cargo check --workspace --exclude interop`, and `rtk launch cargo test --manifest-path accel-rpc/tonic/Cargo.toml -p tonic-dsa-bytes-async --test hardware_dsa -- --ignored --nocapture`.
  Full `rtk cargo check --workspace` failed only in `interop/build.rs` because required `protoc` / `protoc-gen-rust-grpc` binaries are not configured in this environment.

## Interface finding

`poll_encode` is sufficient to model asynchronous DSA execution and item ownership across `Pending`. The current direct-buffer experiment adds a low-level delayed `EncodeBuf` commit API and assumes the reserved final buffer allocation remains stable while DSA is pending.
