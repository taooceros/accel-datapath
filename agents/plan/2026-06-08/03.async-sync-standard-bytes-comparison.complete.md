# Agent plan: async vs sync DSA vs standard bytes comparison

## Goal

Build and run a three-way Tonic mock bytes RPC throughput comparison for standard CPU, synchronous DSA, and asynchronous DSA encode copies.

## Constraints

- Keep the comparison in `tonic-dsa-bytes-async` and avoid disturbing the existing sync benchmark binary.
- Use the existing mock unary bytes echo design for parity.
- Do not claim a performance result without a release hardware run.
- Run hardware through `launch` from the repository root so the DSA launcher resolves correctly.

## Steps

1. Add a comparison executable under a neutral benchmark crate.
2. Add the required async/sync DSA dependencies to the benchmark crate.
3. Build and run targeted tests/checks/clippy for the benchmark crate.
4. Run the release comparison through `launch` with `/dev/dsa/wq0.0`.
5. Record raw CSV and interpretation in a benchmarking report.

## Completed work

- Added `compare_bytes_rpc_throughput` under `tonic-bytes-bench/src/bin`.
- Added benchmark dependencies, including `tonic-dsa-bytes-sync` and `tonic-dsa-bytes-async`, to the benchmark crate.
- Implemented a generic benchmark harness that compares standard CPU, sync DSA, and async DSA over the same Tonic unary bytes echo path.
- Verified format, check, tests, clippy, release build, and workspace check excluding `interop`.
- Ran hardware comparison through `launch` on `/dev/dsa/wq0.0` for default payloads, broader payloads, and targeted 1 MiB / 4 MiB repeats.
- Wrote `docs/report/benchmarking/054.async_sync_standard_bytes_rpc_2026-06-08.md`.

## Result

The initial staged-buffer runs did not show a stable end-to-end DSA win. The async path has since been changed to direct final-buffer DSA writes under the stable-buffer experiment assumption; use the latest hardware rows in `docs/report/benchmarking/054.async_sync_standard_bytes_rpc_2026-06-08.md` for current performance.
