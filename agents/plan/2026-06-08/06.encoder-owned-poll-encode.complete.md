# Encoder-owned poll_encode execution plan

## Reader

Coding agents changing the vendored Tonic codec interface for the async DSA encode experiment.

## Objective

Move `Encoder::poll_encode` to a `Body::poll_frame`-like shape: pinned encoder plus context only, with all in-flight encode state owned by the encoder.

## Steps

1. Update the codec trait to separate encode start from encode polling.
2. Refactor `EncodedBytes` so it tracks only frame-level state and delegates item/pending operation ownership to the encoder.
3. Update prost, raw bytes, JSON/example, transport, benchmark, sync DSA, and async DSA encoder implementations.
4. Preserve the current fast CPU path and direct async DSA buffer behavior.
5. Run focused tests/checks for the touched crates.

## Constraints

- Do not move gRPC framing/compression/max-size logic into individual encoders.
- Do not keep the old `&mut Option<Item>` continuation protocol as a compatibility shim.
- Do not hide DSA pending-storage behavior behind undocumented caller conventions.
