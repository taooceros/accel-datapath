# Experiment 2 mechanism probes agent plan

## Reader

Future agents extending or interpreting the Experiment 2 mechanism-probe module.

## Scope

Implement the follow-up probes as Experiment 2 sub-experiments, not as a new numbered submission-bottleneck experiment. Preserve the existing `submit-marker-overlap` result contract; put new results under a separate selector/result key.

## Steps

1. Capture the design in `docs/report/benchmarking/034...` and a local module note.
2. Add config types for `submit-marker-mechanism` and explicit probe variants if needed.
3. Add a `SubmitMarkerMechanismResult` schema with optional stats for per-read and batch-scan probes.
4. Implement `experiment_2_marker_overlap::mechanism_probes` with one packed baseline spec, 64B-padded completion storage, cacheline-position aggregation, prefetch variants, batch timing, reset/pre-touch/clflush states, and per-row baseline comparisons.
5. Wire the module into `submission_bottleneck.rs`, `report.rs`, `main.rs`, and CLI contract tests.
6. Verify with targeted tests, release build, and a small launch smoke run if hardware remains available.

## Guardrails

- Do not change existing `submit_marker_overlap` JSON fields.
- Do not introduce fake probe rows; each row must execute a real submit/poll loop.
- Keep batch size and concurrency terminology explicit: every probe still submits one logical operation per MMIO; `n` is burst length.
- Keep result names stable and snake_case in JSON.
