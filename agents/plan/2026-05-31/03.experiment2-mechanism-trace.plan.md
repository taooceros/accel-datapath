# Experiment 2 mechanism trace agent plan

## Scope

Add per-iteration trace emission to the Experiment 2 mechanism-probe submodule. Keep the trace JSON compatible with `SubmitMarkerSampleTrace` so the existing trace plotter can draw mechanism rows.

## Steps

1. Extend `SubmitMarkerMechanismResult` with `sample_trace`.
2. Add an iteration trace recorder in `experiment_2_marker_overlap::mechanism_probes` that captures submit latency and poll-event read order/status/latency.
3. Feed that trace recorder from both per-read and batch-scan timing paths without duplicating call arguments.
4. Extend `plot_submit_poll_trace.py` with mechanism row selection, defaulting to `baseline/packed-32b` when plotting mechanism JSON.
5. Verify with tests, release build, hardware run, JSON shape validation, and generated plot.

## Guardrails

- Do not change existing `submit_marker_overlap` JSON fields.
- Keep mechanism baseline semantics unchanged: packed 32B, reset-only, no prefetch, per-read timing.
- Batch-scan rows may have window timing rather than per-read latencies; per-read rows must support the same latency-order plot as the baseline trace.
