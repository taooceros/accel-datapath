# DSA payload latency benchmark execution plan

## Goal

Implement and verify a focused `hw-eval` DSA benchmark for one-operation memmove completion latency across payload sizes.

## Scope

- Inspect current DSA benchmark routing, result shape, and CLI contract tests.
- Add a DSA-only `payload-latency` selector using existing latency reporting.
- Update tests and README examples enough that the CLI contract is explicit.
- Build release and run hardware measurements via `launch` for 1MiB, 10MiB, 100MiB, and 1GiB.

## Non-goals

- Do not redesign the full DSA benchmark matrix.
- Do not add batching or concurrency to this benchmark; the requested signal is one operation completion latency.
- Do not run hardware-facing binaries directly outside `launch`.

## Verification completed

- `rtk cargo fmt -p hw-eval`
- `rtk cargo test -p hw-eval --test cli_contract`
- `rtk cargo test -p hw-eval config::tests::remaining_dsa_only_benchmarks_reject_iax`
- `rtk cargo build --release -p hw-eval`
- `launch ./target/release/hw-eval --accel dsa --benchmark payload-latency --device /dev/dsa/wq0.0 --iterations 3 --sizes 1048576,10485760,104857600,1073741824 --json --pin-core 0`

## Outcome

Completed. The earlier long run was caused by fixed 100-copy warmup per size plus DSA page-fault training. The final implementation makes payload-latency warmup size-aware and pre-touches payload pages before timing.
