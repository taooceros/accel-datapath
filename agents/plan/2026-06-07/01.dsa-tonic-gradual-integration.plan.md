3. Route only eligible Prost encode payloads through a staged DSA memmove; keep the default CPU path unchanged.
4. Validate DSA completion explicitly and return tonic errors on setup or completion-status failures.
5. Add focused tests for configuration state, threshold policy, and missing-device error behavior.
6. Run targeted package tests/checks with and without the DSA feature.
7. Update completion notes in the human plan and this execution plan.

## Completion notes

Completed. The implementation kept Tonic's default Prost path unchanged unless `tonic-prost` is built with `dsa` and `set_process_dsa_config(Some(...))` selects a message by size. The DSA path stages Prost output, submits a raw memmove descriptor into reserved tonic output capacity, and advances the readable buffer length only after success.
