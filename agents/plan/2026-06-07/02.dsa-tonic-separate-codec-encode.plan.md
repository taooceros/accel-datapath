# Agent plan: tonic-prost-dsa-sync encode codec

## Reader

Future agents continuing the experimental DSA/Tonic codec work in `accel-rpc/tonic`.

## Steps

1. Keep the ordinary `tonic-prost` crate as the CPU-only baseline.
2. Add a separate workspace crate named `tonic-prost-dsa-sync`.
3. Implement `DsaSyncProstCodec<T, U>` and `DsaSyncProstEncoder<T>` in the new crate; reuse `tonic_prost::ProstDecoder<U>` for decode.
4. Keep DSA support unconditional in the new crate, since the crate itself is the opt-in experimental surface.
5. Use a shared DSA work queue handle (`SharedDsaWorkQueue = Arc<DsaWorkQueue>`) rather than a process `RwLock` checked on every encode.
6. Implement the synchronous staged DSA memmove path: encode to staging, submit one memmove descriptor into tonic output spare capacity, spin until completion, then advance output length only on success.
7. Add focused tests for configuration failure, codec construction without process WQ, CPU path without WQ, CPU baseline isolation, and shared-WQ `Send + Sync` bounds.
8. Run targeted tests/checks for the new crate and `tonic-prost`.

## Constraints

- Treat existing gitlink and file changes as in-progress work; do not reset or stash.
- Keep hardware optional for tests.
- Do not fall back to CPU after the DSA sync codec selected DSA for a message.
- Keep this slice encode-only and synchronous; async completion belongs in a later design.
- Avoid generated-code changes unless the user explicitly asks to make DSA the generated default codec.
- Avoid per-message synchronization on the DSA selection path; default codecs clone the shared work queue at construction.

## Completion notes

Completed. DSA sync encode lives in `accel-rpc/tonic/tonic-prost-dsa-sync` rather than in `tonic-prost`. The new crate is the experimental opt-in surface and has DSA enabled unconditionally. `tonic-prost` remains the CPU-only baseline. The DSA hot path now uses an optional shared work queue stored on the codec/encoder, avoiding process `RwLock` reads per message. The only tonic core change is `EncodeBuf::put_uninit_slice_with`, which lets the DSA crate initialize reserved output capacity and advance the readable length only after success.
