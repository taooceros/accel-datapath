# Submit occupancy one-extra execution plan

## Goal

Add the first implementation slice from the DSA submission bottleneck experiment plan while keeping the experiment code clean, narrow, and findable.

## Scope

- Read the existing `hw-eval` CLI, report, and DSA methodology patterns.
- Add the one-extra-submit benchmark selector and JSON schema.
- Put the experiment runner in a dedicated DSA bottleneck module rather than burying it in the legacy DSA benchmark file.
- Add targeted host-free tests and documentation.

## Steps

1. Extend config parsing for `submit-occupancy`, occupancies, and DSA operation class.
2. Extend report output with a skipped-when-empty `submit_occupancy` array.
3. Implement the hardware runner with unique descriptor/completion slots and whole-phase timing.
4. Wire the runner into the DSA benchmark dispatcher.
5. Update README and targeted tests.
6. Run narrow verification: config/report tests, CLI contract tests, and release build.
