# Experiment 2 hot-loop optimization

## Goal
Reduce avoidable CPU-side overhead in `submit-marker-overlap` without changing the JSON/report contract or the experiment question.

## Scope
- Kept Experiment 2 zero-based indexing and direct submit timing.
- Reused preallocated scratch buffers for per-poll observations.
- Moved sample-trace vector materialization out of the submit/poll loop.
- Deferred request-completion accumulator updates until after the submit loop by recording observed TSC/status/index in scratch arrays.
- Preallocated trace accumulator storage for fixed per-iteration fields.

## Verification
- `cargo fmt -p hw-eval`
- `cargo test -p hw-eval experiment_2_marker_overlap`
- `cargo check -p hw-eval`
- `cargo build --release -p hw-eval`

- `perf report --stdio` and `perf report --stdio --no-children`
