# Agent execution plan: submit admission probe

## Objective

Add a DSA hardware experiment that distinguishes “dedicated WQ `movdir64b` blocks until accepted” from “overrun submissions can be lost or left without completions.”

## Target files

- `hw-eval/src/config.rs`
- `hw-eval/src/main.rs`
- `hw-eval/src/methodology/dsa.rs`
- `hw-eval/src/report.rs`
- `hw-eval/README.md`
- `docs/report/benchmarking/018.dsa_submit_workload_study_2026-05-24.md`

## Design

Add `--benchmark submit-admission` for DSA only. For each configured `--submit-bursts` value, each iteration will:

1. reset `N` completion records;
2. submit `N` distinct completion-bearing NOOP descriptors as a tight `movdir64b` burst without inflight tracking;
3. measure only the submit loop;
4. poll all completion records with a bounded scan loop;
5. report completed count statistics plus submit-loop timing.

Interpretation:

- If completion count remains equal to submitted count after the WQ depth, `movdir64b` behaved as blocking/admission-paced for this device/run.
- If completion count falls below submitted count, dedicated-WQ overrun produced missing completions and software inflight tracking is required for correctness, not just latency.

## Verification

- `cargo fmt --package hw-eval`
- `cargo test -p hw-eval`
- `cargo build --release -p hw-eval`
- Hardware run through `launch` with dense burst points around 128.

## Non-goals

- Do not reconfigure WQs in code.
- Do not add a raw PCIe BAR sink experiment in this pass.
- Do not change existing submit-only timing semantics.
