# Agent execution plan: submit-only measurement cleanup

## Objective

Clean up DSA submit-only benchmark output so measurement-source artifacts are visible and JSON consumers can identify timer source without inferring it from optional fields.

## Target files

- `hw-eval/src/config.rs`
- `hw-eval/src/main.rs`
- `hw-eval/src/methodology/dsa.rs`
- `hw-eval/src/report.rs`
- `hw-eval/README.md`
- `docs/report/benchmarking/018.dsa_submit_workload_study_2026-05-24.md`

## Steps

1. Add `--submit-bursts` parsing and config validation, defaulting to `1,2,4,8,16,32,64,128,256,512`.
2. Thread `submit_bursts: &[usize]` to the DSA submit-only path.
3. Add `timer: Option<&'static str>` to `LatencyResult` and populate it only for submit-only timer rows.
4. Add empty calibration rows through the generic `bench_submit_only_workload<T: SubmitTimer>` path by allowing an empty/no-submit workload mode.
5. Rename the sustained JSON benchmark label to `submit_only_pressure_ramp`; keep the existing CLI selector name unless tests reveal a better low-risk change.
6. Update docs and targeted tests.

## Verification

- `cargo fmt --package hw-eval`
- `cargo test -p hw-eval`
- `cargo build --release -p hw-eval`
- `launch ./target/release/hw-eval --accel dsa --benchmark submit-only --submit-mode all --device /dev/dsa/wq0.0 --json --iterations 1000 --sizes 64 --submit-bursts 1,64 --pin-core 0`

## Non-goals

- No `--timer-source`.
- No nested timer sampling.
- No `rdpmc` implementation in this pass.
- No shared-WQ or `enqcmd` support in this pass.
