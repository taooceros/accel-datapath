# Agent execution plan: timer-source measurements

## Objective

Add generic timer-source support to `hw-eval` and use it in DSA submit-only workloads to report wall-clock ns, invariant TSC ticks, and PMU core cycles.

## Target files

- `hw-eval/src/submit.rs`
- `hw-eval/src/report.rs`
- `hw-eval/src/methodology/dsa.rs`
- `docs/report/benchmarking/018.dsa_submit_workload_study_2026-05-24.md`

## Implementation steps

1. Add `TimerSample` and `MeasurementTimers` to `submit.rs`.
2. Implement wall and TSC sampling with `Instant` and existing `rdtscp`/`lfence`.
3. Implement Linux PMU thread-local CPU cycle counter with `perf_event_open`:
   - type: `PERF_TYPE_HARDWARE`
   - config: `PERF_COUNT_HW_CPU_CYCLES`
   - disabled at open
   - exclude kernel/hv
   - pid: 0, cpu: -1, group_fd: -1
   - reset/enable before measured closure; disable/read after.
4. Add optional stats fields to `LatencyResult`: `tsc_ticks`, `wall_ns`, `core_cycles`.
5. In submit-only benchmark, gather vectors for all timer sources and populate optional fields.
6. Keep existing `cycles` as TSC ticks and `ns` as wall-clock ns for submit-only rows.
7. Verify with fmt/test/release build and one hardware run.

## Notes

Do not add dependencies. Use `libc` directly. PMU unavailability is not fatal; omit `core_cycles` rather than failing the benchmark.
