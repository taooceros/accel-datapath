# Agent execution plan: DSA submit workload study

## Reader

Future coding agent continuing the DSA submit-only benchmark work.

## Objective

Implement a small, explicit submit-only workload family in `hw-eval`, run gradual release/hardware checks, and record a report that separates unloaded MMIO issue cost from backpressure and fence serialization.

## Files expected to change

- `hw-eval/src/config.rs`
- `hw-eval/src/main.rs`
- `hw-eval/src/submit.rs`
- `hw-eval/src/methodology/dsa.rs`
- `docs/report/benchmarking/018.dsa_submit_workload_study_2026-05-24.md`

## Implementation sequence

1. Add `SubmitOnlyMode` to CLI/config with values `all`, `unloaded`, `sustained`, and `mfence`.
2. Pass `config.submit_mode` into `run_dsa_benchmarks`.
3. Add an inline `mfence()` helper beside `lfence()` in `hw-eval/src/submit.rs`.
4. Refactor `bench_submit_only_same_desc` into a tiny dispatcher over `SubmitOnlyWorkload` values.
5. Implement three named modes:
   - `submit_only_unloaded`: timed burst plus sentinel drain outside measured region.
   - `submit_only_sustained`: current no-poll/no-drain timed burst.
   - `submit_only_mfence`: timed burst with `mfence` between adjacent submissions plus sentinel drain outside measured region.
6. Keep burst points fixed at `1,2,4,8,16,32,64,128,256,512`.
7. Keep `--benchmark all` from becoming unexpectedly long: run only the unloaded submit-only baseline in the normal all-DSA suite; run all submit modes only under `--benchmark submit-only --submit-mode all`.

## Verification sequence

1. `cargo fmt --package hw-eval`
2. `cargo test -p hw-eval`
3. `cargo build --release -p hw-eval`
4. Hardware through launcher, release binary only:
   - unloaded mode
   - sustained mode
   - mfence mode
   - combined all mode if individual modes succeed

## Reporting

Write `docs/report/benchmarking/018.dsa_submit_workload_study_2026-05-24.md` with:

- exact commands run;
- table of burst median cycles/batch and cycles/submit for each mode;
- interpretation using the Host Network credit/backpressure lens;
- clear distinction between MMIO issue, admission/backpressure, and completion latency.
