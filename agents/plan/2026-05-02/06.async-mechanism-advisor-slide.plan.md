# Agent plan: async mechanism advisor slide

## Reader and task

This is the execution plan for creating an advisor-facing mini-sequence comparing `stdexec`, Rust Tokio, and C++ coroutine async mechanisms. The human-facing design plan is `docs/plan/2026-05-02/05.async-mechanism-advisor-slide.plan.md`.

## Steps

1. Locate the target presentation deck or ask which deck should receive the slide if unclear.
2. Read the surrounding slides to match narrative level, terminology, and visual density.
3. Implement the 5-slide sequence from the human plan unless the target deck has severe time/space constraints:
   - shared lifecycle slide;
   - `stdexec` operation graph slide;
   - Tokio/Rust polling + lifetime proof slide;
   - C++ coroutine suspension/frame slide;
   - advisor comparison table slide.
4. Add the optional Rust lifetime backup slide only if the deck can tolerate one more slide or if the advisor discussion needs concrete API constraints.
5. Keep the slides conceptual and evidence-bounded, using `docs/report/research/002.async_mechanism_description_sources.md` as source notes:
   - `stdexec` as an explicit lazy sender/receiver operation graph that starts through connection/operation state.
   - Tokio as runtime-driven polling, `Waker` wakeup, pinned futures, task scheduling, and lifetime/ownership constraints.
   - For Tokio/Rust, explicitly highlight the lifetime challenge: buffers and completion records that cross `.await` must have valid ownership/lifetimes; spawned tasks impose `'static + Send`; pinned futures constrain movement after polling.
   - C++ coroutine as language-level `co_await` suspension/resumption where coroutine frames store continuation state and libraries provide policy.
6. Compile the deck and run a text-level sanity check.
7. Update the human plan completion notes if the slides are implemented.

## Constraints

- Do not add new performance or hardware claims.
- Do not modify code for this task.
- Prefer the 5-slide sequence over one crowded slide; cut the optional backup first if space is tight.
- Keep terminology accessible to someone who knows systems but may not remember each async framework's details.
- Treat the Tokio/Rust lifetime slide as the highest-priority design element.
