# Raw NUMA0 hw-eval thread sweep rerun plan

## Goal

Delegate a hardware-facing rerun of the raw `hw-eval` DSA shared-WQ thread sweep so the Tokio NUMA0 characteristics report can compare against raw NUMA0 data for all relevant submitter thread counts, not only the existing 32T/64T spot-checks.

## Scope

- Target device: `/dev/dsa/wq0.1` shared DSA WQ.
- Operation: DSA direct/no-batch memmove (`batch_n=1` conceptual baseline).
- Placement: NUMA node 0 CPU + memory via `numactl --cpunodebind=0 --membind=0`.
- Thread counts: `1,2,4,8,16,32,64`.
- Message sizes: `128,256,1024,4096`.
- Concurrency cap: at least `128` so `memmove_mt_t<N>` rows include the report's `concurrency=128` points.
- Output directory: `docs/report/benchmarking/shared_thread_sweep_numa0/`.

## Constraints

- Use `launch` / `tools/build/dsa_launcher`; do not run the hardware binary directly.
- Build release binaries only.
- Preserve existing artifacts until new outputs are clearly named or intentionally refreshed.
- Stop and report if hardware setup, launcher, or permission fails.
- Do not edit presentation files from the subagent unless explicitly requested; return artifact paths and summary values.

## Expected output

- Raw JSON and raw launcher logs for every requested thread count, preferably named consistently with the existing convention:
  - `docs/report/benchmarking/shared_thread_sweep_numa0/hw_eval_wq0_1_numa0_threads<N>.json`
  - `docs/report/benchmarking/shared_thread_sweep_numa0/hw_eval_wq0_1_numa0_threads<N>.raw`
- A concise summary table for `memmove_mt_t<N>` at `concurrency=128`, sizes `128,256,1024,4096`, including Mops/s and GB/s.
- Any failures in `docs/report/benchmarking/shared_thread_sweep_numa0/failures.log` or a new clearly named failure log.

## Verification

- Confirm each JSON parses with `jq`.
- Confirm each requested thread count has `memmove_mt_t<N>` rows.
- Confirm the `concurrency=128` rows exist for sizes `128,256,1024,4096`.
