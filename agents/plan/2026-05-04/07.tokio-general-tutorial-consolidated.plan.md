## Context shortcut

For future edits, remember this chain:

```text
blocking stack stores continuation
→ many waits make one-thread-per-wait expensive
→ event loop multiplexes fewer workers
→ each paused operation needs explicit continuation state
→ C uses context + callback
→ Go uses stackful goroutine stacks
→ Rust/C++ use stackless future/coroutine state machines
→ Tokio polls/wakes/schedules Rust futures
→ spawn moves futures into runtime-owned tasks
→ lifetimes, Send, and Pin fall out of saved task state
```

## Editing rules

- Keep visible slide text audience-facing, not plan-facing.
- Do not re-add visible meta statements such as `No hardware details`, `No stdexec`, or `self-contained tutorial deck`.
- Avoid `Takeaway:` prefixes; write the claim directly.
- Preserve the pressure -> mechanism -> consequence flow.
- Keep `tokio::spawn` precise: multi-thread spawn stores the future in the runtime, and the spawned future and output must be `Send + 'static`.
- Explain `'static` as no short-lived borrowed references in the saved future, not as leaking forever.
- For `Send`, focus on values live across `.await`.
- For `Pin`, stay conceptual unless explicitly asked for library/unsafe details.
