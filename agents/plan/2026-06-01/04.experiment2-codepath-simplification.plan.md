# Experiment 2 codepath simplification execution plan

## Goal

Refactor the Experiment 2 overlap codepath so the benchmark loop reads as submit, poll, observe, aggregate, while preserving behavior.

## Scope

- Edit `hw-eval/src/benchmarks/submission_bottleneck/experiment_2_marker_overlap/overlap.rs` only unless tests expose a required caller/test adjustment.
- Do not change CLI selectors, JSON field names, or benchmark semantics.
- Do not run hardware-facing binaries directly; verification is compile/unit-test level unless hardware launch is explicitly required.

## Steps

1. Encapsulate flattened per-iteration trace storage.
2. Encapsulate completion observation state.
3. Update unit tests to assert the helper contract rather than internal scratch details.
4. Format and run targeted tests.

## Verification

Use targeted `cargo test -p hw-eval` invocations for the affected helper tests and CLI/config tests, plus `cargo fmt`.

## Completion notes

Implemented. Added `OverlapScratch`, `OverlapCase`, `CompletionObservations`, and `IterationTrace` so the main runner only enumerates cases and each case follows submit/poll/observe/aggregate. Moved the one-shot `measured_call` helper into `common.rs` and reused it in both Experiment 2 overlap and mechanism probe submit/poll timing. Kept `CompletionStorage` completion access explicit rather than using `Index`/`IndexMut`, because the storage type contains both descriptors and completion records. Replaced separate mechanism polling entry points with one `poll_to_next_unfinished` path and modeled poll batching as `poll_submit_batch_n`, the number of submitted requests between poll events. Added helper unit tests for active trace length and poll-submit-batch semantics. Verification passed with `cargo fmt -p hw-eval`, `cargo test -p hw-eval experiment_2_marker_overlap --lib --bins`, `cargo test -p hw-eval`, and `cargo build --release -p hw-eval`.
