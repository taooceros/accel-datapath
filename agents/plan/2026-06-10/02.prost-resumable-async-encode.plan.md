# Agent plan: Prost resumable async encode

## Reader

Coding agent implementing the Prost-only async encode state redesign.

## Goal

Make generated Prost poll encoders resume precisely across pending payload-copy operations, including repeated fields, maps, and nested messages, while keeping Tonic untouched.

## Steps

1. Inspect existing `PollEncodeState`, generated scalar/map/message code, and generated-message tests.
2. Add cursor support to `PollEncodeState` for nested message polling and keep payload-copy state in the sink-owned state slot.
3. Change generated message-field polling to write enclosing key/length once, descend into a nested cursor, and resume nested payload copies exactly.
4. Add focused tests with a sink that returns `Poll::Pending` once per payload and compare async output byte-for-byte with synchronous encode.
5. Run focused and existing Prost tests from `accel-rpc/tonic/prost`.

## Constraints

- No boxed futures in the hot Prost encode path.
- No borrowed `BufMut` or encode buffer may survive `Poll::Pending`.
- Do not touch Tonic codec/body code.
- Keep CPU encode as the default fast path.

## Verification

Use targeted `message_encoding` tests first, then run the relevant Prost package tests.

## Completion

- Implemented nested cursor stack support in `PollEncodeState`.
- Routed generated message, map-message-value, and oneof polling through resumable poll helpers.
- Added pending-once generated-message tests for scalar-only, plain payload, repeated, map, and nested-message cases.
- Verified with targeted async encode tests, full Prost workspace tests, and diff whitespace checks.
