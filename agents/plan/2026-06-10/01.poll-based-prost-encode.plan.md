# Agent plan: poll-based async Prost encode

## Reader

Coding agent continuing the DSA/Tonic/Prost async encode thread.

## Goal

Replace the boxed/generated-future async Prost experiment with a poll-based API that keeps the encode path concrete and allocation-free while preserving the DSA payload-copy hook.

## Steps

1. Inspect current `prost::Message`, async encode helper, derive-generated code, tests, and `tonic-dsa-bytes-async` Prost codec.
2. Add poll-based traits/types in `prost` that can be implemented by generated messages and driven by the existing async encode wrapper.
3. Generate message-local encode state for string/bytes-capable fields and delegate non-beneficial fields to synchronous encode.
4. Refactor the DSA Prost codec top-level encode future to a concrete state machine with no `Box::pin` / `Pin<Box<dyn Future>>`.
5. Update or add tests for CPU equivalence, pending/resume behavior, and DSA error propagation.
6. Run targeted checks and hardware smoke, then update the project plan completion notes.

## Constraints

- Do not add boxed futures or dynamic-dispatch futures.
- Do not change normal `Message::encode`, `encode_raw`, or default CPU output.
- Keep DSA internals in `tonic-dsa-bytes-async`.
- Hardware-selected DSA errors must surface; do not silently CPU-fallback after selection.

## Verification

Use focused Cargo checks/tests for `prost`, `prost-derive`, `tonic-prost-async`, and `tonic-dsa-bytes-async`, then run the ignored hardware smoke through `launch`.

## Completion

- Implemented the poll-based Prost encode API and concrete DSA Prost encode future.
- Preserved synchronous defaults for small and non-accelerable messages.
- Verified Prost CPU equivalence, pending/resume behavior, DSA codec tests, and hardware smoke.
