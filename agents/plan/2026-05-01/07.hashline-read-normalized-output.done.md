# Hashline read normal-looking output plan

## Goal
Make the project-local Pi `read` override avoid the visible `LINE+ID|TEXT` gutter format while preserving anchor-based `edit` safety.

## Scope
- Update `.pi/extensions/hashline.ts` only.
- Keep `edit` anchors as `LINE+ID` strings such as `160sr`.
- Keep stale-anchor diagnostics actionable.
- Avoid changing repository domain code.

## Intended changes
- Change formatted read lines from `LINE+ID|TEXT` to a tab-prefixed anchor form (`LINE+ID<TAB>TEXT`).
- Update display sanitization and prefix-stripping helpers so render output and copied read lines continue to behave correctly.
- Update tool descriptions/guidance/help text to no longer document the pipe-separated format.

## Verification
- Run a narrow direct smoke check against a temporary file to verify read output has anchors without `|`, edit can use those anchors, and copied prefixed read lines are stripped from edit content.
- Run a renderer smoke check to verify displayed read output no longer includes hashline prefixes.
- Run a Pi extension load check for `.pi/extensions/hashline.ts`.

## Completion notes
Changed `.pi/extensions/hashline.ts` so model-visible read output uses `LINE+ID<TAB>TEXT` instead of `LINE+ID|TEXT`, the read renderer strips anchor prefixes for normal-looking displayed file content, and copied read lines still strip their hashline prefix when used as edit content. Verified with direct temporary-file read/edit and read-render smoke checks plus a Pi extension load check.
