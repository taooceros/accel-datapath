# Hashline rendering polish plan

## Goal

Make the project-local hashline tools friendlier for humans in Pi's UI while preserving the anchor-rich tool content that the model needs for safe edits.

## Scope

- Update `.pi/extensions/hashline.ts` only.
- Keep `hashline_read` and `hashline_edit` tool-result content unchanged for the model.
- Add custom TUI renderers that hide the two-letter hash suffix from displayed line anchors.
- Render hashline edit diffs through Pi's normal diff renderer so edits look like patch output in the UI.

## Intended changes

- Add a small display-only sanitizer that converts `123ab|text` to `123|text` and applies the same cleanup to diff/error display text.
- Add compact `renderCall` labels for both tools.
- Add `renderResult` for reads and edits; edit results should prefer `details.diff` rendered through `renderDiff`.

## Verification

- Run the direct temporary-file smoke test again to verify the model-visible behavior still supports read, edit, creation, and stale-anchor rejection.
- Import/register the extension in a tiny script and call renderers directly enough to verify displayed output hides hash suffixes and edit rendering uses scrubbed diffs.
