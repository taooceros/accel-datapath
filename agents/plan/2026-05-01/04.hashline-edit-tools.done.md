# Hashline edit tools extension plan

## Goal

Add project-local Pi extension tooling that mimics Oh My Pi's hashline editing workflow: read a file with stable per-line anchors, then edit by referring to those anchors instead of copying large exact-text blocks.

## Scope

- Add a `.pi/extensions/hashline.ts` extension.
- Register a read-style tool that emits `LINE+ID|TEXT` anchors.
- Register an edit-style tool that applies append/prepend/range operations against those anchors and rejects stale references.
- Keep the implementation self-contained and avoid changing domain code.

## Intended changes

- Use a deterministic short line hash in the read and edit tools.
- Preserve common file properties where practical: UTF-8 text, BOM, and original line endings.
- Resolve paths relative to Pi's working directory and serialize read-modify-write operations through Pi's file mutation queue.
- Return compact diff previews and actionable stale-anchor errors.

## Verification

- Run a small direct tool-level smoke script against a temporary file to verify read anchors, replacement, insertion, deletion, and stale-anchor rejection.
- Avoid running broad project tests because this only adds a Pi extension and does not affect Rust/C++ domain code.

## Completion notes

Implemented `.pi/extensions/hashline.ts` with `hashline_read`, `hashline_edit`, and `/hashline-help`.
