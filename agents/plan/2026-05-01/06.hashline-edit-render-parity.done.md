# Hashline edit render parity plan

## Goal

Make `hashline_edit` look and behave much closer to Pi's built-in `edit` renderer: compact header, normal colored diff, and no hashline fingerprints in human-facing edit output.

## Scope

- Update `.pi/extensions/hashline.ts` only.
- Keep `hashline_read` model content anchored so the model can still copy full `LINE+ID` references.
- Change `hashline_edit` execution details/rendering to use a normal line-numbered edit diff instead of a hashline-flavored diff preview.
- Add a built-in-edit-style self-rendering shell with preview-in-call behavior.

## Intended changes

- Replace the custom `---/+++ @@` hashline diff preview with a copy of Pi's normal line-numbered diff algorithm.
- Make `hashline_edit` tool content concise (`Updated`/`Created` plus change counts), with the full diff in `details.diff` for rendering.
- Add a `Box`-based `renderCall`/`renderResult` flow mirroring the built-in edit tool.
- Keep display sanitization for stale-anchor errors and read output.

## Verification

- Run a direct behavior/render smoke test that checks edit behavior, stale-anchor rejection, concise no-hash edit content, and renderer output with no hash suffix.
- Run a Pi extension load check.

## Completion notes

Implemented standard-tool overrides in `.pi/extensions/hashline.ts`: `read` now emits model-visible hashline anchors while rendering like a normal read for humans, `edit` now uses hashline anchors but renders through a built-in-edit-style self shell with normal line-numbered diffs, and `write` now replaces the built-in write path with a text-file writer. The diff generation is self-contained and does not require the external `diff` package. Verified with temporary-file override/render smoke tests and a Pi extension load check.
