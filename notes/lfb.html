lfb: does a MOVDIR64B need a fill buffer (LFB) to leave the core?

Probe: dsa-lab/src/bin/lfb_mov.rs. Run directories are relative to dsa-lab-runs/.

Background (pushpull): one core keeps ~30 MOVDIR64B in the CHA TORs at once, more than the ~16 fill buffers a Golden Cove core is said to have, so a MOVDIR64B does not hold a fill buffer until the CHA releases it. Open: does it use one at all (briefly, as a WC buffer, per the SDM's "WC protocol"), or does its data wait in the store-buffer entry until the CHA takes it?

Design (written before running)

Fill the fill buffers with software prefetches, then send one MOVDIR64B right away. Prefetches are used instead of loads because a load miss blocks in-order retirement, so a later MOVDIR64B could not leave the store buffer until the load data returns (that would measure load latency, not fill-buffer contention). A prefetch that misses L1 takes a fill buffer until its line returns, but does not hold up retirement of later instructions.

Per trial (submitter cpu 4, poller cpu 6, both node 0; dsa0 wq0.0; heaters, mesh ~2.2 GHz):

  1. N target lines, one per 4 KiB page, flushed with CLFLUSHOPT (or pre-loaded into L1 for the control); MFENCE; idle 2 µs.
  2. t_pre; N × PREFETCHT0; t_s (lfence; rdtsc; lfence).
  3. MOVDIR64B of a noop with a completion record (descriptor in L1); MFENCE; t_f.
  4. The poller stamps t_p when the record changes.

Measured per N: issue = t_s − t_pre, arrival = t_p − t_s, fence = t_f − t_s. Targets: l1 (control: no fill buffer used), local (node-0 DRAM), remote (node-1 DRAM, longer occupancy). Variant empty: the same without the MOVDIR64B, to see whether MFENCE itself waits for outstanding prefetches. N = 0, 8, 12, 14, 15, 16, 17, 18, 20, 24, 32. Blocks rotate over targets and N.

Predictions:

  • Calibration: for DRAM targets, issue jumps once N exceeds the number of fill buffers F (prefetch N = F + 1 must wait for a line to return); flat for l1. If no knee appears, the prefetches are not holding fill buffers and the test says nothing.
  • H-FB (MOVDIR64B needs a fill buffer to leave the core): for N ≥ F, arrival rises by about the time until the first prefetch returns (local tens of ns up to ~100 ns, remote more, remote > local); flat below F and flat for l1.
  • H-noFB (it leaves from the store buffer without one): arrival flat (within ~5 ns) at every N for all targets.
  • fence is only interpretable if empty stays flat; otherwise MFENCE waits for the prefetches.

  • Calibration: issue jumps at N = 17 for DRAM targets (local +118 ns, remote +167 ns), flat for l1: 16 prefetches get a fill buffer at once, the 17th waits for a line to return. L1D.REPLACEMENT = N + 1–1.6 per trial: the prefetches really fill lines. With N ≥ 17 the prefetches all return within a few ns of each other, so at t_s the fill buffers are free again; only N = 15–16 keep them busy at t_s.
  • H-FB: supported, two evidence types, two core pairs. With 15 or 16 fill buffers busy, the MOVDIR64B reaches the device later by +86–89 ns (local) and +147–148 ns (remote), i.e. it leaves when the first prefetch returns; with ≤ 14 busy, no delay; l1 flat. FB_FULL counts the wait directly: local 229–275 cycles at 2.8–3.25 GHz ≈ 82–86 ns, remote 465–473 cycles at 3.25 GHz ≈ 143–146 ns, matching the arrival delays.
  • H-noFB: ruled out.
  • The threshold is 15 busy, not 16: prefetches can use 16, a MOVDIR64B (and an MFENCE) waits when 15 are busy [INFERENCE: one fill buffer is not available to stores / fences].
  • MFENCE alone (empty) also waits for a fill buffer: +86–95 ns local, +145–150 ns remote at N = 15–16, with matching FB_FULL cycles. So the MOVDIR64B + MFENCE column mixes both waits.
  • With the pushpull result (one core keeps ~30 MOVDIR64B in the CHA TORs, 16 fill buffers), a MOVDIR64B holds its fill buffer only briefly, not until the CHA releases it [INFERENCE: the fill buffer is freed once the 64 B have been handed on, so for most writes waiting in the CHA the data has already left the L1 fill buffers; whether it sits in the CHA or in another core-side queue (e.g. L2) is not measured].
  • Practical: cache-missing loads, prefetches or completion-record polls that occupy ≥ 15 fill buffers delay a submit by up to one memory latency.

Not independently audited yet; replicated on a second core pair.
