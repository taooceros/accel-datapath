arb_io: E4 — Do two devices behind the same IO stop compete for write bandwidth?

Question

On Intel Sapphire Rapids, dsa0 (PCI BDF 75:01.0) and iax1 (PCI BDF 75:02.0) share the same root bus (0000:75) and IO stop on NUMA node 0 (Socket 0). Conversely, dsa2 (PCI BDF f2:01.0) sits on root bus 0000:f2 on NUMA node 1 (Socket 1) behind an independent IO stop.

When multiple cores drive both devices near their maximum arrival rates using MOVDIR64B with rotating portal offsets (16 lines, achieving ~5-6.5 ns/write per core solo), does the shared IO stop on node 0 arbitrate or bottleneck write bandwidth between dsa0 and iax1?

Setup and Workload

  • Devices:
    • dsa0: DWQ wq0.0 (dedicated, size 128, 4 engines, group 0).
    • iax1: DWQ wq1.0 (dedicated, size 128, 1 engine, group 0; high arrival rate causes expected WQ-full drops, but device PMU EV_DWQ_SUCCESS + EV_DWQ_FULL captures all arriving writes).
    • dsa2: DWQ wq2.0 (dedicated, size 128, 4 engines, group 0) on node 1.
  • Traffic pattern:
    • Each submitter core executes MOVDIR64B round-robin across 16 distinct 64-byte offsets of its assigned portal page (offset = 64 * (k % 16)).
    • Noop descriptors with completion records pointing to local pre-faulted cache-line aligned memory.
    • Submissions run in synchronized burst windows (50 ms) using a shared TSC deadline.
  • Core allocation:
    • dsa0 submitters: disjoint physical cores on node 0 (e.g. cpus 2, 4, 6, 8).
    • iax1 submitters: disjoint physical cores on node 0 (e.g. cpus 10, 12, 14, 16).
    • dsa2 submitters: physical cores on node 1 (e.g. cpus 34, 36, 38, 40).
    • Coordinator core: cpu 20 (node 0).
    • Heaters: 8 L2 spinner threads on node 0 (cpus 24..31) and 8 on node 1 (cpus 56..63), holding mesh frequency at ~2.2 GHz.
  • Phases:
    • Phase A: dsa0 alone driven by node-0 submitters.
    • Phase B: iax1 alone driven by disjoint node-0 submitters.
    • Phase C: dsa0 + iax1 driven concurrently by their disjoint node-0 core sets.
    • Phase D_ctrl: dsa2 alone driven by node-1 submitters.
    • Phase D: dsa0 (node-0 cores) + dsa2 (node-1 cores) driven concurrently (control: separate IO stops).

Competing Hypotheses (written before any runs)

Hypothesis 1: Shared IO stop arbitrates / limits write bandwidth (H-arb)

  • The root bus 75 IO stop or mesh ingress port has a finite write bandwidth / transaction ingestion rate that saturates under concurrent multi-core rotated-offset blasts.
  • Predictions:
    1. In Phase C, the combined arrival rate is strictly less than the sum of solo arrival rates: $C_{\text{sum}} < A + B$.
    2. Back-pressure from the IO stop reaches the cores' store buffers, resulting in a measurable increase in per-core ns/write in Phase C compared to Phase A and Phase B.
    3. In Phase D, because dsa2 is on a separate IO stop on Socket 1, no shared bus arbitration occurs: $D_{\text{sum}} \approx A + D_{\text{ctrl}}$, and dsa0 per-core ns/write matches Phase A.

Hypothesis 2: No shared limit at these arrival rates (H-nolimit)

  • The IO stop / root complex ingress crossbar on node 0 has sufficient capacity to sink writes to both devices concurrently without throttling.
  • Predictions:
    1. In Phase C, the combined arrival rate equals the sum of solo arrival rates: $C_{\text{sum}} \approx A + B$.
    2. Per-core ns/write on dsa0 and iax1 remains flat between solo and concurrent phases.
    3. In Phase D, $D_{\text{sum}} \approx A + D_{\text{ctrl}}$, with flat per-core ns/write.

Evidence Types

  1. Core-side timing and submit rates:
    • Per-core ns/write measured via high-resolution TSC delta over submitted writes ($(\Delta \text{TSC} \times 10^9) / (\text{hz} \times N_{\text{writes}})$).
    • Core-reported write issue rate (M writes/s).
  2. Device PMU arrival counters:
    • EV_DWQ_SUCCESS (0x10) + EV_DWQ_FULL (0x20) on dsa0, iax1, and dsa2.
    • Verified with time_enabled == time_running (no multiplexing).
  3. Uncore IIO counters:
    • uncore_iio_0 event UNC_IIO_TxN_REQ_BY_CPU.MEM_WRITE (0xc1, umask 0x01, ch_mask 0xff, fc_mask 7) on node 0 (cpu 0) and node 1 (cpu 32).
    • Independent verification of CPU posted writes entering the IO stop.

Detailed Analysis and Findings

1. Same-IO-Stop Competition (Phase C vs A + B)

  • In Phase A and Phase B, solo driving of either dsa0 or iax1 reaches an ingress rate of ~141.2 M writes/s (dsa0) and ~142.0 M writes/s (iax1).
    • With 4 cores, each core submits at ~28.3 ns/write (aggregating to ~141 M/s).
    • With 2 cores, each core submits at ~14.1 ns/write (aggregating to ~141 M/s).
    • Expected sum without contention: $A + B = 141.2 + 142.0 = \mathbf{283.2\text{ M writes/s}}$ ($18.1\text{ GB/s}$ posted write bandwidth).
  • In Phase C (concurrent submissions to dsa0 and iax1 behind the same IO stop on root bus 75):
    • In the 4-core run, combined arrival rate drops to 238.7 M writes/s ($C_{\text{sum}} / (A + B) = \mathbf{0.843}$, a 15.7% bandwidth deficit). Both devices are symmetrically throttled from 141-142 M/s down to 119.3 M/s.
    • In the 2-core run, combined arrival rate drops to 208.2 M writes/s ($C_{\text{sum}} / (A + B) = \mathbf{0.735}$, a 26.5% bandwidth deficit). Both devices drop symmetrically to 104.1 M/s.
    • In the 1-core run (unsaturated), attempted total arrival rate is only $84.3 + 83.9 = 168.2\text{ M/s}$. Here, $C_{\text{sum}} = 168.5\text{ M/s} \approx A + B$, proving that arbitration/bottlenecking requires saturation above ~170-200 M writes/s.

2. Core-Side Timing and Back-Pressure

  • In Phase C, submitter cores directly experience store-buffer backpressure:
    • 4-core run: per-core ns/write rises from 28.33 ns (solo) to 33.54 ns (Phase C), a +18.4% latency increase (+5.2 ns/write).
    • 2-core run: per-core ns/write rises from 14.14 ns (solo) to 19.22 ns (Phase C), a +35.9% latency increase (+5.1 ns/write).
  • The fact that ns/write rises for both sets of cores while executing non-blocking MOVDIR64B confirms that posted-write credits or store-buffer drain buffers into the IO stop are exhausted, propagating backpressure directly into the CPU core's store pipeline.

3. Cross-Socket Control (Phase D vs A + D_ctrl)

  • In Phase D, dsa0 (node 0) and dsa2 (node 1) are driven concurrently. dsa2 sits behind root bus 0000:f2 on Socket 1, an independent IO stop.
    • dsa0 arrival rate: 141.22 M/s (identically matching Phase A solo: 141.20 M/s).
    • dsa0 per-core ns/write: 28.32 ns (identically matching Phase A solo: 28.33 ns).
    • dsa2 arrival rate: 141.10 M/s (identically matching Phase D_ctrl solo: 141.14 M/s).
    • Combined throughput: $D_{\text{sum}} = 141.22 + 141.10 = \mathbf{282.32\text{ M writes/s}}$.
    • Ratio $D_{\text{sum}} / (A + D_{\text{ctrl}}) = \mathbf{1.000}$ (100.0% efficiency, zero degradation).
  • This confirms that the contention observed in Phase C is strictly localized to the shared IO stop on node 0, and does not arise from software coordination, memory overhead, or cross-socket mesh interference.

4. Triangulation with Uncore IIO Counters

  • The uncore IIO counter uncore_iio_0 (UNC_IIO_TxN_REQ_BY_CPU.MEM_WRITE):
    • In Phase A: Node 0 counts 141.4 M/s, Node 1 counts 0.0 M/s.
    • In Phase B: Node 0 counts 142.3 M/s, Node 1 counts 0.0 M/s.
    • In Phase C: Node 0 counts 239.3 M/s, Node 1 counts 0.0 M/s (matching $119.3 + 119.4 = 238.7\text{ M/s}$ PMU sum within 0.2%).
    • In Phase D_ctrl: Node 0 counts 0.0 M/s, Node 1 counts 141.4 M/s.
    • In Phase D: Node 0 counts 141.5 M/s, Node 1 counts 141.4 M/s (summing to 282.9 M/s).
  • The exact quantitative match between core submits, uncore IIO transactions, and device PMU arrival sums rules out any descriptor loss or counter multiplexing artifact (mux=false everywhere).

Verdict

Hypothesis 1 (H-arb: Shared IO stop arbitrates / limits write bandwidth) HOLDS.

  1. Competition under saturation: When two devices behind the same IO stop (dsa0 and iax1 on root bus 75) are driven concurrently near saturation, they compete for write bandwidth. Combined arrival rate drops by 15.7% (4 cores/dev, from 283.2 to 238.7 M/s) to 26.5% (2 cores/dev, from 283.4 to 208.2 M/s).
  2. Back-pressure reaches cores: Submitter cores experience store-buffer backpressure, with per-core ns/write increasing by +18.4% (4 cores/dev: 28.3 → 33.5 ns) to +35.9% (2 cores/dev: 14.1 → 19.2 ns).
  3. Control isolates the IO stop: Driving devices behind independent IO stops (dsa0 on node 0 + dsa2 on node 1) achieves perfect linear additivity ($D_{\text{sum}} = A + D_{\text{ctrl}} = 282.3\text{ M writes/s}$, ratio 1.000) with zero rise in per-core ns/write.
  4. Saturation threshold: At low traffic (1 core/dev, combined rate ~168 M writes/s = 10.8 GB/s), no arbitration is observed ($C \approx A + B$). Contention sets in once aggregate posted write traffic approaches the node-0 IO stop limit of ~210-240 M writes/s (~13.4-15.3 GB/s) [INFERENCE].
